# RUNBOOK: демо переиспользования префикса (prompt caching) на локальной модели

Показывает тот же механизм, что лежит в основе prompt caching у Anthropic и OpenAI —
переиспользование уже посчитанного состояния модели для неизменного префикса запроса —
но на локальной модели через Ollama, без облачного API и без биллинга.

## Окружение

- Ollama 0.32.13 (сервер), доступен на `http://localhost:11434` — если у вас другой хост,
  подставьте свой в переменную окружения `OLLAMA_HOST` перед запуском.
- Модель `qwen2.5:7b` (7B, ~4.7 ГБ на диске), должна быть скачана заранее.
- Python 3.12, пакет `ollama` 0.6.2 из `requirements.txt`.
- GPU не нужен, тесты прогонялись на CPU (Apple Silicon), время из примеров ниже — с этой
  машины и будет отличаться на вашей.

## Шаг 1. Поднять Ollama и скачать модель

```bash
ollama serve &
ollama pull qwen2.5:7b
```

Проверка: `curl -s http://localhost:11434/api/tags` должен вернуть JSON со списком моделей,
где есть `qwen2.5:7b`.

## Шаг 2. Окружение Python

```bash
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
```

Проверка: `./.venv/bin/pip show ollama` печатает `Version: 0.6.2`.

## Шаг 3. Прогнать демо

```bash
./.venv/bin/python3 cache_prefix_demo.py
```

Скрипт делает пять вызовов подряд к одной и той же модели с длинным неизменным системным
промптом (карточки тарифов вымышленного SaaS-продукта, ~900 токенов) и печатает для каждого
вызова `prompt_eval_count` (сколько токенов промпта в запросе) и `prompt_eval_duration_s`
(сколько реального времени ушло на обработку промпта):

1. `turn1_cold_prefix` — первый вызов с полным префиксом, с нуля.
2. `turn2_continue_same_prefix`, `turn3_continue_same_prefix` — тот же диалог продолжается
   новыми вопросами, префикс не меняется.
3. `turn4_prefix_changed_one_char` — новый диалог с тем же префиксом, но с одним изменённым
   символом.
4. `turn5_original_prefix_out_of_sequence` — точный повтор запроса №1, отправленный не сразу
   после себя, а после запроса №4.

Проверка, что демо действительно показало эффект (числа у вас будут другие, соотношение —
похожим): у `turn2` и `turn3` значение `prompt_eval_duration_s` должно быть в разы меньше, чем
у `turn1`, при том что `prompt_eval_count` у них не меньше, а больше (диалог длиннее). У
`turn4` время должно вернуться к уровню `turn1` — это и есть промах кэша. Что покажет `turn5`,
скрипт не подгоняет — это открытый вопрос, ради которого демо и снято.

В конце скрипт печатает сводную таблицу JSON и короткий текстовый вывод по всем пяти замерам.

## Если не так

- **`ollama: command not found`** — Ollama не установлена или не в `PATH`, см.
  https://ollama.com/download.
- **`curl: (7) Failed to connect`** — сервер Ollama не поднят, выполните `ollama serve` в
  отдельном терминале (или как сервис) и повторите.
- **Модель качается на первом вызове по 40-90 секунд** — это ожидаемо для `ollama pull`,
  дождитесь окончания; если то же самое происходит в `cache_prefix_demo.py`, значит модель не
  была скачана заранее, вернитесь к шагу 1.
- **Все пять замеров одинаково медленные** — вероятная причина: Ollama не в режиме `keep_alive`
  между вызовами (например, между запусками скрипта прошло больше 5 минут и модель выгрузилась
  из памяти) или на машине уже не хватает оперативной памяти для 7B-модели и она выгружается
  сама. Проверьте `ollama ps` — модель должна оставаться в списке между вызовами.
- **`prompt_eval_count` не совпадает с числами из примера** — нормально, зависит от токенизатора
  версии модели и точного текста промпта; важна не абсолютная цифра, а соотношение между
  холодным и продолженным вызовом.
