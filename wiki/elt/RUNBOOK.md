# ELT-конвейер на Python и SQL: воспроизведение демо

Демо показывает ELT целиком: Extract читает сырую таблицу источника как есть, Load копирует её
построчно в целевую базу без единой правки (никакого pandas между extract и load), Transform —
один SQL-запрос, который выполняет сам Postgres после загрузки: дедупликация, чистка региона,
отсев брака, бизнес-фильтр, расчёт выручки и агрегация — всё это работа вычислительной мощности
хранилища, а не отдельного процесса.

## Окружение

| Компонент | Версия |
|---|---|
| Python | 3.12 |
| psycopg | 3.3.4 (пакет `psycopg[binary]`) |
| PostgreSQL | 18.x, локальный |

Что должно быть доступно: работающий сервер PostgreSQL на `localhost:5432` и пользователь,
которому разрешено создавать базы данных. Имя пользователя в скриптах — `techfriends`, замените
на своё. Все адреса локальные.

## Шаг 1. Поставить зависимости

```bash
python3 -m venv .venv
./.venv/bin/python3 -m pip install "psycopg[binary]==3.3.4"
```

## Шаг 2. Подставить своего пользователя БД

В `db_setup.py` и `elt_pipeline.py` замените `user=techfriends` в строках `ADMIN_DSN`/`DSN` на
имя своего пользователя PostgreSQL. Если используете пароль, а не доверительную аутентификацию
по сокету, добавьте в DSN `password=<пароль>`.

## Шаг 3. Поднять источник (Extract-сторону)

```bash
./.venv/bin/python3 db_setup.py
```

Ожидаемый вывод:

```
база elt_demo создана
таблица source.orders пересоздана, строк: 5030
  из них id с дублями: 30, строк с NULL в quantity/unit_price: 52
```

Скрипт идемпотентный: создаёт базу `elt_demo`, если её ещё нет, и каждый раз пересоздаёт таблицу
`source.orders` заново — она имитирует OLTP-источник, из которого в реальном ELT данные забирает
Airbyte/Fivetran/Meltano. 5000 "чистых" строк плюс намеренные дефекты: 30 строк-дублей (как при
повторной выгрузке без сдвига offset), 52 строки с пропуском в `quantity` или `unit_price`, и
часть значений `region` с лишними пробелами или в другом регистре.

## Шаг 4. Прогнать сам конвейер

```bash
./.venv/bin/python3 elt_pipeline.py
```

Ожидаемый вывод — статистика по каждой стадии и замер времени:

```
extract: 5030 строк -> load (как есть, без очистки): 5030 строк в raw.orders_raw
transform (один SQL-запрос внутри базы): 902 строк в analytics.sales_summary
extract+load 0.066 с, transform 0.013 с, итого 0.079 с
```

Дальше — первые 10 строк итоговой таблицы `analytics.sales_summary` (регион, дата, число заказов,
выручка). Числа будут отличаться от примера — данные генерируются случайно при каждом прогоне
`db_setup.py`.

Как понять, что шаг прошёл: код возврата `0`, в `raw.orders_raw` ровно столько же строк, сколько
выгружено из `source.orders` (Load ничего не отфильтровал), число агрегированных строк заметно
меньше исходных 5030 (дубли и брак отсеялись на шаге Transform), и в итоговой таблице ровно
4 региона без разнобоя в написании — это можно проверить отдельно:

```bash
psql -d elt_demo -tAc "SELECT DISTINCT region FROM analytics.sales_summary ORDER BY region;"
```

Ожидаемый вывод: `East`, `North`, `South`, `West` — ровно четыре строки, без вариантов с
пробелами или другим регистром.

Отдельно можно убедиться, что raw-слой действительно сырой, дубли и разнобой региона в нём есть:

```bash
psql -d elt_demo -tAc "SELECT count(*) FROM raw.orders_raw;"
psql -d elt_demo -tAc "SELECT DISTINCT region FROM raw.orders_raw WHERE region ILIKE '%north%' OR region ILIKE '%south%';"
```

## Шаг 5. Прогнать заново

```bash
./.venv/bin/python3 elt_pipeline.py
```

И `raw.orders_raw`, и `analytics.sales_summary` каждый раз пересоздаются перед загрузкой —
повторный прогон безопасен и не накапливает дублей между запусками.

## Если не так

- **`connection refused` на localhost:5432.** Сервер PostgreSQL не запущен либо слушает другой
  порт. Проверьте `psql -c "select 1"` тем же пользователем, что указан в DSN.
- **`FATAL: role "techfriends" does not exist` (или похожее).** В `db_setup.py` и
  `elt_pipeline.py` не заменили `user=techfriends` на своего пользователя — см. шаг 2.
- **`No module named 'psycopg'`.** Ставился пакет `psycopg` без экстры `binary`, либо не тот
  venv активен. Проверьте, что запускаете именно `./.venv/bin/python3`, а не системный `python3`.
- **`relation "source.orders" does not exist».** `elt_pipeline.py` запущен раньше `db_setup.py` —
  сначала обязательно шаг 3, только потом шаг 4.
- **Итоговая таблица пустая или почти пустая.** Проверьте, что в `raw.orders_raw` действительно
  5030 строк (Load отработал) — если там 0, значит упал сам `extract_and_load`, смотрите вывод
  выше по стадии.
