# GraphRAG

Код к Wiki-статье «Что такое GraphRAG» на сайте BigDataSchool: https://bigdataschool.ru/wiki/graphrag/

Демо показывает размен, на котором стоит GraphRAG: индексация прогоняет LLM по всему корпусу и
строит граф знаний, зато на вопросах, где ответ размазан по нескольким документам, поиск идёт по
связям, а не по косинусной близости.

## Состав

- `settings.yaml` — конфигурация graphrag под локальную Ollama через litellm
- `input/` — учебный корпус из девяти коротких документов про клиентов, договоры и подразделения банка
- `rag_baseline.py` — наивный векторный RAG на том же корпусе, нужен как база для сравнения
- `graph_stats.py` — разбор построенного графа и поиск пути между двумя сущностями
- `RUNBOOK.md` — пошаговый прогон с проверками

## Окружение

- Python 3.12 (graphrag требует `<3.14, >=3.11`, на 3.14 не ставится)
- graphrag 3.1.1, litellm 1.92.0, lancedb 0.34.0, networkx 3.6.1
- Ollama 0.32.9 на `http://localhost:11434`
- Модели: `qwen2.5:7b` для генерации, `nomic-embed-text` для эмбеддингов

## Как запустить

1. Создать окружение и поставить зависимости:

```
python3.12 -m venv .venv
./.venv/bin/python3 -m pip install "graphrag==3.1.1" ollama numpy networkx pandas
```

2. Скачать модели: `ollama pull qwen2.5:7b` и `ollama pull nomic-embed-text`
3. Собрать индекс: `graphrag index --root .`
4. Задать вопрос: `graphrag query --root . --method local "ваш вопрос"`

Подробный порядок с проверкой после каждого шага в `RUNBOOK.md`.

## Чего ожидать

Индексация девяти документов на локальной 7b-модели занимает десятки минут. Это не ошибка
настройки, а нормальная стоимость подхода: LLM вызывается на каждый чанк при извлечении сущностей
и ещё раз на каждое сообщество при построении отчётов.
