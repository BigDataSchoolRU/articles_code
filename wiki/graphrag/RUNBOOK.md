# RUNBOOK: GraphRAG на локальной Ollama

Порядок сборки стенда и прогона демо. После каждого шага указано, что должно быть в выводе.

## Окружение

- Python 3.12. Версия важна: graphrag 3.1.1 требует `<3.14, >=3.11` и на 3.14 не установится
- graphrag 3.1.1, litellm 1.92.0, lancedb 0.34.0, networkx 3.6.1, numpy, pandas
- Ollama 0.32.9, доступна по `http://localhost:11434`
- Модели `qwen2.5:7b` и `nomic-embed-text`
- Свободного места около 3 ГБ под пакеты и 5 ГБ под модели

Если Ollama крутится на другом хосте, подставьте свой адрес в поле `api_base` в `settings.yaml`.

## Шаг 1. Окружение и зависимости

```bash
python3.12 -m venv .venv
./.venv/bin/python3 -m pip install --upgrade pip
./.venv/bin/python3 -m pip install "graphrag==3.1.1" ollama numpy networkx pandas
```

Проверка: `./.venv/bin/pip list | grep graphrag` печатает восемь пакетов версии 3.1.1.
Установка тянет около 120 зависимостей, включая spacy и onnxruntime, и занимает несколько минут.

Если увидели ошибку про несовместимую версию Python, значит venv собран не на 3.12. Проверьте
`./.venv/bin/python3 --version` и пересоздайте окружение полным путём к нужному интерпретатору.

## Шаг 2. Модели

```bash
ollama pull qwen2.5:7b
ollama pull nomic-embed-text
curl -s http://localhost:11434/api/tags
```

Проверка: в ответе `api/tags` присутствуют обе модели. Пустой ответ или отказ соединения означает,
что сервер Ollama не запущен.

## Шаг 3. Конфигурация проекта

```bash
./.venv/bin/graphrag init --root . --force -m "ollama_chat/qwen2.5:7b" -e "ollama/nomic-embed-text"
```

Проверка: появились `settings.yaml`, `.env` и каталог `prompts` с тринадцатью файлами.

Дальше `settings.yaml` правится под Ollama. Ключевой момент: litellm склеивает имя модели как
`model_provider/model`, поэтому провайдер и модель задаются раздельно.

```yaml
completion_models:
  default_completion_model:
    type: litellm
    model_provider: ollama_chat
    model: qwen2.5:7b
    api_base: http://localhost:11434
    api_key: ollama
```

Для эмбеддингов провайдер `ollama` без суффикса `_chat`. Готовый конфиг лежит рядом, его можно
взять целиком.

Проверка: `./.venv/bin/python3 -c "import yaml; yaml.safe_load(open('settings.yaml'))"` отрабатывает молча.

## Шаг 4. Индексация

```bash
./.venv/bin/graphrag index --root .
```

Проверка: в конце вывода строка `Pipeline complete`, в каталоге `output` появились
`entities.parquet`, `relationships.parquet`, `communities.parquet`, `community_reports.parquet`
и каталог `lancedb`.

Это самый долгий шаг. На девяти коротких документах и локальной 7b-модели он занимает от семи
минут до часа в зависимости от того, насколько заполнен кэш. Прогресс видно по строкам
`extract graph progress: N/9` в `logs/indexing-engine.log`.

Повторные запуски используют кэш в каталоге `cache`, поэтому пересчитываются только изменившиеся
документы. Удаление `cache` означает полный пересчёт со всеми затратами.

## Шаг 5. Разбор графа

```bash
./.venv/bin/python3 graph_stats.py
```

Проверка: печатается стоимость каждого этапа индексации, число узлов и рёбер, список сущностей по
типам и путь между двумя сущностями с указанием числа переходов.

## Шаг 6. Сравнение с наивным векторным RAG

```bash
TOP_K=3 ./.venv/bin/python3 rag_baseline.py
```

Проверка: печатаются найденные фрагменты с косинусной близостью и ответ модели. На вопросе про
дирекцию модель должна сообщить, что связей не хватает.

## Шаг 7. Запросы к GraphRAG

```bash
./.venv/bin/graphrag query --root . --method local "В какую дирекцию банка входит подразделение, которое обслуживает ООО Северный Ветер?"
./.venv/bin/graphrag query --root . --method global "О чём этот корпус документов в целом?"
```

Проверка: local search называет Северо-Западную дирекцию. Global search выдаёт обзор корпуса,
собранный из отчётов по сообществам.

## Если не так

**Установка падает на версии Python.** graphrag 3.1.1 не поддерживает 3.14. Соберите venv на 3.12
или 3.13 и повторите установку.

**Индексация падает с ошибкой соединения.** Проверьте, что Ollama отвечает по адресу из `api_base`,
и что в конфиге для чат-модели указан провайдер `ollama_chat`, а не `ollama`.

**Индексация висит без движения.** Посмотрите `logs/indexing-engine.log`. Если прогресс идёт, но
медленно, это нормально: каждый чанк это отдельный вызов модели.

**В графе дубли и искажённые имена.** Ожидаемое поведение маленькой модели. Лечится более крупной
моделью, доработкой промпта `prompts/extract_graph.txt` под вашу предметную область и явным
списком типов сущностей в `entity_types`.

**Отчёты по сообществам выходят по-английски на русском корпусе.** Штатные промпты graphrag
написаны по-английски, и небольшие модели наследуют язык инструкции. Правится переводом промптов
в каталоге `prompts`.
