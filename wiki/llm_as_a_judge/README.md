# LLM-as-a-Judge

Код к статье [LLM-as-a-Judge](https://bigdataschool.ru/wiki/llm_as_a_judge/).

Две демонстрации механизма LLM-as-a-Judge на локальных моделях через Ollama: оценка одного
ответа по явной рубрике (single-answer grading) и попарное сравнение двух ответов с проверкой
на position bias — смещение вердикта судьи в сторону позиции ответа в промпте, а не его
содержания. Всё считается локально на CPU, GPU не нужен.

## Состав

| Файл | Что внутри |
|---|---|
| `single_answer_grading.py` | кандидат отвечает на вопрос, судья оценивает ответ по рубрике из 4 критериев (accuracy, completeness, clarity, safety), возвращает JSON-вердикт |
| `pairwise_position_bias.py` | сильная и слабая модель отвечают на один вопрос, судья сравнивает пару дважды с переставленными позициями ответов |
| `RUNBOOK.md` | пошаговая инструкция с ожидаемым выводом и разбором типовых граблей |

## Окружение

macOS 26.5.2 (arm64), Ollama 0.32.13, python-клиент `ollama` 0.6.2. Модели: `qwen2.5:7b`
(кандидат-генератор и сильная модель в паре), `qwen2.5:0.5b-instruct-q4_0` (слабая модель в
паре), `llama3.1:8b` (судья).

## Как запустить

```bash
ollama pull qwen2.5:7b
ollama pull qwen2.5:0.5b-instruct-q4_0
ollama pull llama3.1:8b
pip install ollama
python3 single_answer_grading.py
python3 pairwise_position_bias.py
```

Подробности по шагам, ожидаемый вывод и что делать, если пошло не так, — в
[RUNBOOK.md](RUNBOOK.md).

## Что получилось на прогоне

В single-answer grading судья `llama3.1:8b` оценил развёрнутый ответ `qwen2.5:7b` про
переобучение на максимум по всем четырём критериям (4/4/4/4, итог 20/20) — модель дала точный,
полный и практичный ответ, придраться судье было не к чему.

В pairwise-сравнении судья оба раза (и с исходным порядком ответов, и с переставленным)
выбрал ответ сильной модели `qwen2.5:7b` как более точный и конкретный по сравнению с более
расплывчатым ответом слабой квантованной `qwen2.5:0.5b-instruct-q4_0`. Position bias на этой
паре вопрос-ответы не проявился: вердикт следовал за содержанием, а не за позицией в промпте.
Это тоже валидный результат — bias систематический, а не гарантированный на каждом запросе,
поэтому проверка на нём обычно проводится на наборе вопросов, а не на одном.

Отдельная грабля, найденная при отладке демо: в первой версии промпта для pairwise-сравнения
формат ответа судьи был задан как `WINNER: A|B|tie` — и `llama3.1:8b` в части прогонов дословно
повторяла этот шаблон с вертикальными чертами вместо того, чтобы выбрать один вариант. Судья
чувствителен к формулировке инструкции по формату вывода: помогла явная инструкция без символа
`|` и с примером корректной строки ответа.
