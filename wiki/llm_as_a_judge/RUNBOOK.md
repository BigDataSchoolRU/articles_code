# RUNBOOK: LLM-as-a-Judge

Демо к статье показывает два основных режима LLM-as-a-Judge: оценку одного ответа по рубрике
(single-answer grading) и попарное сравнение двух ответов (pairwise comparison) с проверкой на
position bias.

## Что должно быть готово

- Python 3.9+.
- Локально запущенная Ollama (https://ollama.com) с тремя моделями:
  ```bash
  ollama pull qwen2.5:7b
  ollama pull qwen2.5:0.5b-instruct-q4_0
  ollama pull llama3.1:8b
  ```
  Проверка, что сервис отвечает:
  ```bash
  curl -s http://localhost:11434/api/tags
  ```
- Python-зависимость:
  ```bash
  pip install ollama
  ```
- GPU не требуется, всё считается на CPU. `qwen2.5:7b` и `llama3.1:8b` — модели по 4.7-4.9 ГБ,
  первый вызов после запуска Ollama прогревает веса и идёт заметно дольше последующих.

## Шаг 1. Single-answer grading

```bash
python3 single_answer_grading.py
```

Скрипт задаёт кандидату (`qwen2.5:7b`) технический вопрос про переобучение, затем передаёт
вопрос и ответ судье (`llama3.1:8b`) вместе с рубрикой из четырёх критериев. Ожидаемый вывод:
текст ответа кандидата, затем JSON вида
`{"accuracy": <1-5>, "completeness": <1-5>, "clarity": <1-5>, "safety": <1-5>, "total": <сумма>,
"verdict": "<обоснование>"}`.

## Шаг 2. Pairwise comparison и position bias

```bash
python3 pairwise_position_bias.py
```

Скрипт получает ответы на один вопрос от сильной (`qwen2.5:7b`) и слабой
(`qwen2.5:0.5b-instruct-q4_0`) моделей, затем дважды прогоняет судью (`llama3.1:8b`) на одной
и той же паре ответов: сначала с исходным порядком, затем с переставленным. Ожидаемый вывод —
два вердикта в формате `WINNER: A|B|tie` с обоснованием и итоговая строка, которая переводит
"A"/"B" каждого прогона в "какая модель победила" и сообщает, обнаружен ли position bias
(победитель сменился вместе с позицией, а не с содержанием).

## Если не так

- **`ConnectionError` при обращении к `localhost:11434`.** Ollama не запущена — поднимите
  её (`ollama serve`) и проверьте `curl` из раздела выше.
- **Модель не найдена.** Она не скачана — выполните соответствующий `ollama pull` из раздела
  «Что должно быть готово».
- **`не распознано (сбой формата у судьи)` вместо A/B/tie.** Судья не выдержал формат первой
  строки ответа (например, приписал лишний текст или значок) — это тоже наблюдаемое поведение
  LLM-as-a-Judge, а не баг скрипта: судья чувствителен к формулировке инструкции по формату
  вывода.
- **Вердикты в single-answer grading не парсятся в JSON.** Судья иногда оборачивает JSON в
  markdown-блок ```` ```json ```` или добавляет пояснение до/после — скрипт вытаскивает первую
  `{...}` регулярным выражением; если и это не сработало, в выводе будет `{"parse_error": true,
  "raw": "<сырой ответ судьи>"}`.
- **Итоговые оценки или вердикты отличаются от примеров в README.** Вывод LLM недетерминирован
  между прогонами (в скрипте задан `temperature=0` для судьи, но кандидат отвечает без фиксации
  температуры) — конкретные числа и формулировки могут отличаться, важна структура и механизм,
  а не точные значения.
