# RUNBOOK: гибридный поиск (BM25 + векторный поиск + RRF)

Локальное демо без Docker и без внешних API. Два независимых поисковика по
одному корпусу — лексический (BM25) и векторный (эмбеддинги) — и их слияние
методом Reciprocal Rank Fusion (RRF).

## Окружение

- Python 3.10+ (демо написано и прогнано на 3.12.13)
- Ollama, запущенная локально на `http://localhost:11434` (адрес по умолчанию)
- Модель `nomic-embed-text` в Ollama
- Пакеты: `rank-bm25`, `ollama` (python-клиент), `numpy`

Подставьте свой адрес Ollama, если она развёрнута не на `localhost`.

## Шаг 1. Поднять Ollama и скачать модель эмбеддингов

```bash
ollama serve &          # если Ollama ещё не запущена как сервис
ollama pull nomic-embed-text
curl -s http://localhost:11434/api/tags | grep nomic-embed-text
```

Ожидаемый результат: в выводе `curl` встречается `nomic-embed-text`. Значит
модель на месте и API отвечает.

## Шаг 2. Виртуальное окружение и зависимости

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install rank-bm25 ollama numpy
```

Ожидаемый результат: `pip install` завершается без ошибок, версии — любые
актуальные на момент установки (демо прогнано на `rank-bm25` 0.2.2, `ollama`
0.6.2, `numpy` 2.5.2).

## Шаг 3. Сравнить лексический и векторный поиск отдельно

```bash
python3 bm25_vs_vector.py
```

Ожидаемый результат: два топ-5 списка — «BM25 (лексический)» и «Векторный
поиск (семантический)» — с разными числами в скобках (BM25-score и
косинусное сходство соответственно) и, как правило, разным порядком
документов. Расхождение в порядке — ожидаемое поведение: два метода
ранжируют по разным сигналам.

## Шаг 4. Слить оба списка через RRF

```bash
python3 rrf_fusion.py
```

Ожидаемый результат: сначала печатаются те же топ-5 BM25 и топ-5 векторного
поиска (без скора у BM25-списка — в RRF от него нужна только позиция), затем
блок «После RRF-слияния» со строками вида
`1. [rrf=0.03279, bm25_rank=1, vector_rank=1] <текст документа>`. Документ,
которого нет в одном из списков, помечен `bm25_rank=—` или `vector_rank=—`,
но всё равно попадает в итоговый список, если высоко стоял во втором.

## Если не так

- **`ConnectionRefusedError` / таймаут при обращении к `localhost:11434`** —
  Ollama не запущена. Проверьте `curl -s http://localhost:11434/api/tags`.
- **`nomic-embed-text` не найдена** — модель не скачана, повторите
  `ollama pull nomic-embed-text`.
- **Косинусное сходство у всех документов почти одинаковое (0.6-0.7 у всех
  подряд, без явного лидера)** — в коде подставляются task-префиксы
  `search_query: ` и `search_document: ` перед текстом: `nomic-embed-text` —
  асимметричная модель, без префиксов сходство запрос-документ считается
  некорректно. Если правите код и префиксы выпали, верните их.
- **BM25 отдаёт много документов с score 0.000** — нормально: BM25 не
  находит ни одного общего слова с запросом и не подтягивает документ по
  смыслу, в отличие от векторного поиска. Именно это и есть повод для
  гибридной схемы.
