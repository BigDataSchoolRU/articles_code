# RUNBOOK: Hallucination Detection — HHEM и RAGAS Faithfulness

Два независимых демо детекции галлюцинаций: классификатор Vectara HHEM-2.1-Open (локально, без
внешних вызовов) и метрика RAGAS Faithfulness с LLM-судьёй через Ollama.

## Окружение

- Python 3.12
- Ollama (только для второго демо), локально по адресу `http://localhost:11434`, модель `qwen2.5:7b`
- Демо 1 (HHEM) и демо 2 (RAGAS) требуют **разных версий `transformers`** — см. ниже, почему.
  Проще всего завести под них два отдельных виртуальных окружения.

Подставьте свои значения там, где ниже написано `<...>`.

## Шаг 1. Окружение для HHEM

```bash
python3.12 -m venv .venv_hhem
.venv_hhem/bin/pip install "transformers==4.46.3" "torch==2.13.0"
```

**Почему именно 4.46.3.** Модель HHEM грузится через `trust_remote_code=True` — вместе с весами
с Hugging Face тянется кастомный Python-код архитектуры. Этот код не обновлялся под внутренний
рефакторинг `transformers`, который переименовал атрибут, отвечающий за tied weights. На
`transformers` 5.x (проверено на 5.15.1) загрузка падает:

```
AttributeError: 'HHEMv2ForSequenceClassification' object has no attribute
'all_tied_weights_keys'. Did you mean: '_tied_weights_keys'?
```

`transformers==4.46.3` подтверждена прогоном как рабочая версия.

## Шаг 2. Запуск демо HHEM

```bash
.venv_hhem/bin/python3 hhem_scoring_demo.py
```

**Что должно быть в выводе.** Первый вызов скачивает веса модели (~600 МБ) с Hugging Face,
занимает от нескольких секунд до минуты в зависимости от сети. Дальше — четыре строки вида
`FCS=0.9150 (выше порога 0.5)` с текстом пары под каждой и итоговое наблюдение про пару 4
(перефраз без дословных совпадений получает низкий скор при фактической точности).

**Как понять, что шаг прошёл.** Пары 2 и 3 (явные галлюцинации) должны получить `FCS` заметно
ниже 0.5, пара 1 (дословное повторение) — заметно выше.

## Шаг 3. Окружение для RAGAS

```bash
python3.12 -m venv .venv
.venv/bin/pip install ragas langchain-ollama
```

Поднимите Ollama и скачайте модель-судью, если её ещё нет:

```bash
ollama serve &
ollama pull qwen2.5:7b
curl -s http://localhost:11434/api/tags   # должен вернуть JSON со списком моделей
```

## Шаг 4. Запуск демо RAGAS Faithfulness

```bash
.venv/bin/python3 ragas_faithfulness_demo.py
```

**Что должно быть в выводе.** Три строки вида `1.000 | полностью согласован с контекстом` с
текстом ответа под каждой. На один вызов судья тратит 25-35 секунд, весь прогон — около полутора
минут.

**Как понять, что шаг прошёл.** Первый случай (ответ полностью подтверждён контекстом) должен
получить `1.000`, третий (место и число зрителей выдуманы) — `0.000`, второй (часть верна, часть
выдумана) — дробное значение между ними.

## Если не так

- **`ModuleNotFoundError: No module named 'langchain_community.chat_models.vertexai'`** при
  импорте `ragas`. Это баг самого пакета `ragas` версии 0.4.3 (issues #2741, #2745, #2753 в
  репозитории `vibrantlabsai/ragas` на GitHub): импорт `ragas` безусловно тянет `ChatVertexAI` из
  `langchain_community`, даже если Vertex AI не используется вообще. На дату написания статьи
  официального фикса нет. `ragas_faithfulness_demo.py` уже содержит обходной путь (заглушка
  модуля в `sys.modules` перед импортом `ragas`) — просто запустите файл как есть.

- **`httpx.ConnectError: All connection attempts failed`** при запуске демо RAGAS. Ollama не
  поднята или слушает не на 11434. Проверьте `curl -s http://localhost:11434/api/tags` — пустой
  ответ или отказ в соединении значит, что сервер не запущен: `ollama serve &`.

- **`AttributeError: ... 'all_tied_weights_keys'`** при загрузке HHEM. Установлена слишком свежая
  версия `transformers`. Переустановите ровно `transformers==4.46.3` в окружение `.venv_hhem`
  (см. шаг 1) — смешивать её с окружением RAGAS не нужно, поэтому и заведены два venv.

- **Скачивание весов HHEM зависает или обрывается.** Первый запуск идёт в Hugging Face Hub без
  токена — при нестабильной сети попробуйте ещё раз, кэш уже скачанных файлов переиспользуется.
