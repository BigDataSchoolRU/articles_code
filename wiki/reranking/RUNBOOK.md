# RUNBOOK: reranking — переранжирование результатов поиска

Демо к статье показывает разницу между поиском по эмбеддингам (baseline) и вторым
проходом cross-encoder'ом (reranking): один и тот же запрос и один и тот же корпус
документов, два разных порядка выдачи.

## Что должно быть готово

- Python 3.12+.
- Локально запущенная Ollama (https://ollama.com) с моделью эмбеддингов:
  ```bash
  ollama pull nomic-embed-text
  ```
  Проверка, что сервис отвечает:
  ```bash
  curl -s http://localhost:11434/api/tags
  ```
- Python-зависимости:
  ```bash
  pip install ollama sentence-transformers
  ```
- GPU не требуется, всё считается на CPU. Модель reranker'а `cross-encoder/ms-marco-MiniLM-L-6-v2`
  (около 90 МБ) скачается автоматически при первом запуске и осядет в кэше Hugging Face.

## Шаг 1. Baseline: поиск по эмбеддингам

```bash
python3 -c "from retrieve import baseline_retrieve; from corpus import DOCUMENTS, QUERY; \
[print(r[0], round(r[2],4)) for r in baseline_retrieve(QUERY, DOCUMENTS, 5)]"
```

В выводе — пять пар `id_документа score`, отсортированных по убыванию косинусного
сходства. Это top-5 кандидатов, которых увидит следующий шаг.

## Шаг 2. Полный прогон: baseline плюс reranking

```bash
python3 demo.py
```

Ожидаемый вывод: сначала список top-5 по эмбеддингам с cosine-скорами, затем тот же
список после cross-encoder reranking с новыми скорами и итоговое сравнение порядка
(`Порядок изменился: True/False`). На корпусе из RUNBOOK порядок меняется: документ,
который отвечает на вопрос по существу, но не совпадает с запросом дословно,
поднимается наверх только после reranking.

## Если не так

- **`ConnectionError` при обращении к `localhost:11434`.** Ollama не запущена — поднимите
  её (`ollama serve`) и проверьте `curl` из раздела выше.
- **Модель `nomic-embed-text` не найдена.** Она не скачана — выполните `ollama pull nomic-embed-text`.
- **Первый вызов reranker'а занимает несколько секунд, а не миллисекунды.** Это
  нормально: конструктор `CrossEncoder(...)` даже с уже закэшированными весами
  инициализирует модель и токенизатор заново при каждом запуске процесса. Повторные
  вызовы `predict()` в рамках одного процесса на порядок быстрее.
- **Предупреждение про `HF_TOKEN` в консоли.** Не ошибка, а совет ускорить закачку с
  Hugging Face Hub через токен. Для этого демо не требуется.
- **Порядок в baseline не совпадает с примером выше.** Эмбеддинги детерминированы, но
  версия модели `nomic-embed-text` могла обновиться — проверьте версию через
  `ollama list`.
