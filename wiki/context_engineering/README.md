# Context engineering

Код к статье [Context engineering](https://bigdataschool.ru/wiki/context_engineering/).

Три демо на локальной модели через HTTP API Ollama показывают, из чего складывается окно
LLM-агента и что дают две базовые операции context engineering: отбор фрагментов вместо
«всего в окно» и компакция длинной истории. Метрики везде одни и те же: верность ответа,
сколько токенов промпта модель прочитала (`prompt_eval_count`) и сколько секунд ушло на их
чтение (префилл).

## Состав

| Файл | Что внутри |
|---|---|
| `01_context_budget.py` | окно агента поддержки собирается из пяти слоёв (системный промпт, 12 инструментов, история с выводами инструментов, документы, вопрос), вклад каждого слоя в токенах |
| `02_select_vs_dump.py` | вопрос по базе из 36 заметок: все заметки в окне (иголка в начале, середине, конце) против top-3 по BM25 на стандартной библиотеке |
| `03_compaction.py` | история агента из шести вызовов инструментов: полная, с очисткой старых выводов инструментов и с резюме от той же модели; два вопроса на раннее требование и на деталь из первого вывода |
| `docker-compose.yml` | Ollama в Docker, если она не установлена локально |
| `RUNBOOK.md` | пошаговая инструкция с ожидаемым выводом и разбором типовых граблей |

## Окружение

Python 3.12, только стандартная библиотека. Ollama 0.40.13, модель `qwen2.5:7b` (4.7 ГБ на
диске). Прогнано на Ubuntu 24.04 x86_64, 4 vCPU без GPU, Ollama в Docker. На CPU модель читает
промпт со скоростью около 9 токенов в секунду, поэтому окно в 2-3 тысячи токенов без кэша
читается 4-5 минут, а полный прогон трёх демо занимает около 25 минут. На GPU те же шаги
идут в десятки раз быстрее.

## Как запустить

```bash
ollama pull qwen2.5:7b
python3 01_context_budget.py qwen2.5:7b
python3 02_select_vs_dump.py qwen2.5:7b
python3 03_compaction.py qwen2.5:7b
```

Адрес Ollama скрипты берут из `OLLAMA_URL`, по умолчанию `http://localhost:11434`.
Подробности по шагам, ожидаемый вывод и что делать, если пошло не так, в
[RUNBOOK.md](RUNBOOK.md).
