# Оркестрация ИИ: supervisor-граф на LangGraph с чекпоинтом в SQLite

Демо к статье поднимает управляющий слой над локальной языковой моделью: узел-супервизор
выбирает исполнителя, состояние графа после каждого шага уходит в SQLite, а второй сценарий
убивает процесс на середине работы и доигрывает граф из сохранённого снимка.

## Окружение

Проверено на macOS 26.5 (arm64), Python 3.12.13. На Linux и Windows отличий по коду нет.

| Компонент | Версия |
|---|---|
| langgraph | 1.2.11 |
| langgraph-checkpoint-sqlite | 3.1.1 |
| langchain-ollama | 1.1.0 |
| Ollama | 0.32.13 |
| Модель | qwen2.5:7b (4,7 ГБ) |

Нужен запущенный Ollama на `http://localhost:11434`. Если у вас он живёт по другому адресу,
подставьте свой в переменную окружения `OLLAMA_HOST` перед запуском.

## Шаг 1. Поставить зависимости

```bash
python3 -m venv .venv
./.venv/bin/python3 -m pip install -r requirements.txt
```

В выводе последней строкой должно быть `Successfully installed ...` со всеми тремя пакетами.

## Шаг 2. Поднять модель

```bash
ollama serve &          # если сервис ещё не запущен
ollama pull qwen2.5:7b
curl -s http://localhost:11434/api/tags | head -c 200
```

Признак успеха: `curl` вернул JSON со списком моделей, и в нём есть `qwen2.5:7b`.

## Шаг 3. Прогнать supervisor-граф

```bash
./.venv/bin/python3 supervisor_graph.py
```

Что должно быть в выводе:

- строки `[суперстеп N]` с растущими размерами полей `notes` и `draft`;
- строки `supervisor -> researcher`, `supervisor -> writer`, `supervisor -> done`;
- готовый абзац после `--- готовый текст ---`;
- список чекпоинтов, по строке на суперстеп плюс стартовый.

На нашем прогоне граф отработал за 22,95 с: супервизор тратил 0,5-0,7 с на решение,
`researcher` 7,27 с, `writer` 13,93 с. Файл `checkpoints.sqlite` занял 4096 байт.

Строку `(модель предложила writer, маршрут отклонён по предусловию)` считайте нормой, а не
ошибкой: модель уровня 7B регулярно предлагает писать текст до того, как собраны факты, и
управляющий узел такой маршрут отклоняет.

## Шаг 4. Проверить возобновление после обрыва

```bash
./.venv/bin/python3 resume_demo.py
```

Скрипт сам запускает первую фазу отдельным процессом и убивает её сигналом KILL сразу после
того, как `researcher` сохранил результат. Признаки того, что шаг прошёл:

- строка `код возврата -9`, то есть процесс действительно убит, а не завершился сам;
- после обрыва в базе лежит непустое поле `notes` и `следующий узел: supervisor`;
- фаза 2 начинается сразу с `supervisor -> writer`, то есть `researcher` повторно не
  вызывается;
- итоговый журнал маршрутизации содержит шаги обоих процессов.

## Если не так

**`httpx.ConnectError: [Errno 61] Connection refused`.** Ollama не запущена. Поднимите
`ollama serve` и повторите: клиент `ollama --version` при этом честно предупреждает
`could not connect to a running Ollama instance`.

**Первый вызов модели идёт втрое дольше остальных.** Это загрузка весов в память. У нас
холодный вызов занял 5,5 с против 0,6 с на тёплом. Перед замерами делайте прогревочный вызов.

**Граф отработал, а возобновлять нечего.** Значит первая фаза успела дойти до конца раньше,
чем прилетел KILL. Проверьте, что вызовы `stream` и `invoke` идут с `durability="sync"`:
при значении по умолчанию снимок пишется асинхронно и обрыв может застать состояние
несохранённым.

**Каждый запуск продолжает старый прогон вместо нового.** Состояние привязано к `thread_id`,
а не к запуску скрипта. Либо смените `thread_id` в конфиге, либо удалите файл
`checkpoints.sqlite` перед прогоном.

**Супервизор ходит по кругу.** Ослабили предусловия в функции `valid`. Управляющий узел
обязан проверять, что предложенный моделью переход вообще возможен в текущем состоянии, иначе
граф упрётся в лимит рекурсии LangGraph.
