# RUNBOOK: LoRA-дообучение языковой модели на локальной машине

Демо к статье [Дообучение модели (Fine-tuning)](https://bigdataschool.ru/wiki/fine_tuning/).

Вы возьмёте базовую модель Qwen2.5-0.5B-Instruct, обучите на ней LoRA-адаптер на выборке из
сорока пар «вопрос — ответ» и сравните, как модель отвечает до и после. Никакой видеокарты
NVIDIA для этого не нужно: всё считается на CPU или на MPS (ускоритель Apple Silicon).

## Окружение

| Что | Значение при прогоне |
|---|---|
| ОС | macOS 26.5.2, arm64 (Apple Silicon) |
| Python | 3.12.13 |
| Ускоритель | MPS, встроенный в torch, отдельной установки не требует |
| Место на диске | около 3 ГБ: веса базовой модели плюс пакеты |
| Сеть | нужна один раз, чтобы скачать модель с Hugging Face Hub |

На Linux с видеокартой всё то же самое поедет на CUDA: в коде выбор устройства сводится к
одной строке, а `torch` подтянется в CUDA-сборке. На машине без ускорителя код отработает на
CPU, только медленнее в несколько раз.

## Шаг 1. Окружение и зависимости

```bash
python3.12 -m venv .venv
./.venv/bin/python3 -m pip install --upgrade pip
./.venv/bin/python3 -m pip install -r requirements.txt
```

Проверка, что ускоритель виден:

```bash
./.venv/bin/python3 -c "import torch; print(torch.__version__, torch.backends.mps.is_available())"
```

Ожидаемый вывод: версия torch и `True`. Если пришло `False`, обучение пойдёт на CPU — это не
ошибка, просто дольше.

## Шаг 2. Выборка

```bash
./.venv/bin/python3 dataset.py
```

Ожидаемый вывод:

```
примеров в обучающей выборке: 40
отложенных терминов: 4
пример: HDFS — распределённая файловая система Hadoop, ... Категория: хранение.
```

Все сорок пар лежат прямо в `dataset.py` списком. Задача дообучения выбрана так, чтобы
результат было видно глазами: модель должна отвечать одной строкой строгого формата
`ТЕРМИН — определение. Категория: <категория>.` вместо нескольких абзацев свободного текста.

Там же лежит `CHAT_TEMPLATE`. Это переписанный шаблон чата Qwen2.5, в котором реплики
ассистента обёрнуты в блок `{% generation %}`. Без такой разметки библиотека не знает, где
кончается вопрос и начинается ответ, и не может считать функцию потерь только по ответу.

## Шаг 3. Обучение адаптера

```bash
./.venv/bin/python3 train_lora.py
```

Что происходит: базовая модель грузится в float32, на проекции внимания `q_proj`, `k_proj`,
`v_proj`, `o_proj` вешаются LoRA-адаптеры ранга 8, базовые веса замораживаются. Дальше восемь
эпох по выборке из сорока примеров.

В выводе смотрите на три вещи:

- строку `обучаемых параметров` — доля от общего числа должна быть меньше процента;
- `loss на старте` и `loss в конце` — второе должно быть заметно меньше первого;
- `адаптер сохранён` — размер каталога `lora_adapter`, это единицы мегабайт против гигабайта
  весов базовой модели.

Рядом появляется `train_metrics.json` с теми же цифрами в машинном виде.

## Шаг 4. Сравнение до и после

```bash
./.venv/bin/python3 compare_before_after.py
```

Скрипт дважды прогоняет одни и те же шесть вопросов: сначала на базовой модели, потом на ней
же с навешенным адаптером. Генерация жадная (`do_sample=False`), поэтому разница в ответах
объясняется адаптером, а не случайностью выбора токенов.

Два вопроса взяты из обучающей выборки, четыре — отложенные, их модель на обучении не видела.
Отложенные и есть главная проверка: перенёсся ли формат ответа на новые термины или модель
просто запомнила сорок строк.

Ожидаемая картина: до дообучения ответ многословный, часто с преамбулой и списком; после —
одна строка нужного формата. Содержание ответов на отложенные термины при этом остаётся на
совести базовой модели, дообучение формату не добавляет модели знаний.

## Если не так

**Ошибка про `{% generation %}` или пустая маска ответа.** Вы применили штатный шаблон чата
модели вместо `CHAT_TEMPLATE` из `dataset.py`. Штатный шаблон Qwen2.5 разметки ответа не
содержит.

**Loss почти не падает.** Восьми эпох на сорока примерах хватает впритык. Поднимите
`num_train_epochs` или ранг `r`, но помните, что на выборке такого размера легко получить
переобучение: модель начнёт выдавать заученные определения на любой вопрос.

**`NaN` в loss на MPS.** Не переводите обучение в float16 на MPS, половинная точность там даёт
нестабильные градиенты. Именно поэтому в коде стоит `dtype=torch.float32`.

**Модель качается медленно или обрывается.** Веса тянутся с Hugging Face Hub без токена, и
неавторизованным запросам достаётся урезанный лимит скорости. Заведите токен и положите его в
переменную окружения `HF_TOKEN`.

**Мало памяти.** Модель на 0.5 млрд параметров в float32 занимает около 2 ГБ плюс состояние
оптимизатора. Если упирается, уменьшите `per_device_train_batch_size` до 1 или `max_length`
до 128.

**Хочется QLoRA.** Квантованная база требует `bitsandbytes`, а он собран под CUDA. На Apple
Silicon этот вариант не запускается, нужна машина с видеокартой NVIDIA.
