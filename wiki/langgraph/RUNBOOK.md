# RUNBOOK: граф агента на LangGraph и локальной модели в Ollama

Пошаговый прогон двух демо-скриптов. После каждого шага написано, что должно быть в выводе.

## Окружение

- Python 3.14
- langgraph 1.2.11, langgraph-checkpoint-sqlite 3.1.1
- langchain 1.3.14, langchain-core 1.5.3, langchain-ollama 1.1.0
- Ollama 0.32.9, слушает http://localhost:11434
- Модель с поддержкой вызова инструментов: qwen2.5:7b или llama3.1:8b, примерно 5 ГБ на диске каждая
- Около 8 ГБ свободной оперативной памяти на модель 7-8B

Адрес Ollama и имя модели читаются из переменных окружения **OLLAMA_URL** и **OLLAMA_MODEL**, подставьте свои значения, если они отличаются.

## Шаг 1. Поставить зависимости

```bash
# протестировано для langgraph 1.2.11, Python 3.14
python3 -m venv .venv
source .venv/bin/activate
pip install "langgraph==1.2.11" "langgraph-checkpoint-sqlite==3.1.1" "langchain==1.3.14" "langchain-ollama==1.1.0"
```

Проверка: команда `pip show langgraph` печатает версию 1.2.11.

## Шаг 2. Убедиться, что модель на месте

```bash
# протестировано для Ollama 0.32.9
ollama --version
ollama list
```

Проверка: в списке есть qwen2.5:7b или llama3.1:8b. Если списка нет, скачайте модель командой `ollama pull qwen2.5:7b`.

## Шаг 3. Проверить, что Ollama отвечает по HTTP

```bash
# протестировано для Ollama 0.32.9
curl -s http://localhost:11434/api/tags | head -c 200
```

Проверка: в ответе приходит JSON со списком моделей. Пустой ответ или отказ в соединении означают, что сервер Ollama не запущен.

## Шаг 4. Прогнать базовый граф

```bash
# протестировано для langgraph 1.2.11, langchain-ollama 1.1.0, Ollama 0.32.9
export OLLAMA_MODEL=qwen2.5:7b
export OLLAMA_URL=http://localhost:11434
python3 agent_graph.py
```

Проверка: в выводе четыре сообщения подряд. Сначала вопрос пользователя, затем ответ модели с вызовом инструмента **course_info**, затем результат инструмента с ценой 66000 и длительностью 6, затем финальный текстовый ответ модели. Если цикл сработал, вызов инструмента и результат инструмента видны обязательно.

## Шаг 5. Повторить прогон на второй модели

```bash
# протестировано для langchain-ollama 1.1.0, Ollama 0.32.9
OLLAMA_MODEL=llama3.1:8b python3 agent_graph.py
```

Проверка: структура вывода та же, формулировка финального ответа может отличаться. Это нормально: код не привязан к конкретной модели.

## Шаг 6. Прогнать граф с паузой на подтверждение

```bash
# протестировано для langgraph 1.2.11, langgraph-checkpoint-sqlite 3.1.1
python3 hitl_approval.py
```

Проверка: сначала печатается строка ПАУЗА НА ПОДТВЕРЖДЕНИЕ с объектом Interrupt и полями course_code и people. Дальше строка со следующим узлом, значение `('tools',)`. После возобновления идут сообщения, среди которых результат инструмента со словом «отправлена». В конце печатается число чекпоинтов в потоке, оно больше единицы.

## Шаг 7. Убедиться, что состояние переживает перезапуск процесса

```bash
# протестировано для langgraph-checkpoint-sqlite 3.1.1
ls -la langgraph_demo.db
python3 - <<'PY'
import sqlite3
from langgraph.checkpoint.sqlite import SqliteSaver
saver = SqliteSaver(sqlite3.connect("langgraph_demo.db", check_same_thread=False))
config = {"configurable": {"thread_id": "demo-1"}}
print("чекпоинтов в базе:", len(list(saver.list(config))))
PY
```

Проверка: файл базы существует, число чекпоинтов больше нуля. Именно эти строки читает граф, когда продолжает прерванный прогон в новом процессе.

## Если не так

- **Соединение с localhost:11434 отклонено.** Сервер Ollama не поднят. Запустите приложение Ollama или команду `ollama serve` и повторите шаг 3.
- **Модель не вызывает инструмент, а отвечает текстом.** Так бывает у моделей 7-8B на длинных формулировках. Задайте вопрос короче и конкретнее либо переключитесь на вторую модель командой из шага 5.
- **Ошибка про ключ tool_calls.** Обычно означает, что взята модель без поддержки вызова инструментов. Проверьте, что в OLLAMA_MODEL стоит qwen2.5:7b или llama3.1:8b.
- **Скрипт с interrupt падает на KeyError по ключу __interrupt__.** Модель не запросила инструмент, значит паузе неоткуда взяться. Повторите прогон с более прямой формулировкой запроса.
- **Второй прогон hitl_approval.py сразу заканчивается.** Поток demo-1 уже доведён до конца и лежит в базе. Удалите файл langgraph_demo.db или поменяйте thread_id в конфиге.
- **Модель отвечает минуты.** Для 7-8B на CPU это ожидаемо. Прогон ускоряет только более лёгкая модель или доступный GPU.
