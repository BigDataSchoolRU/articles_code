# Quantization (квантование модели)

Код к статье [Quantization](https://bigdataschool.ru/wiki/quantization/).

Сравнение трёх GGUF-вариантов одной и той же модели (Qwen2.5 0.5B Instruct: 4-битный, 8-битный
и 16-битный) через Ollama: размер файла на диске, скорость генерации и текст ответа на одном и
том же промпте. Всё считается локально на CPU, GPU не нужен.

## Состав

| Файл | Что внутри |
|---|---|
| `quant_bench.py` | тянет размеры трёх вариантов модели из `ollama list`, дважды вызывает каждый (холодный и тёплый вызов) на одном промпте, печатает сводную таблицу |
| `RUNBOOK.md` | пошаговая инструкция с ожидаемым выводом и разбором типовых граблей |

## Окружение

macOS 26.5.2 (arm64), Ollama 0.32.13, python-клиент `ollama` 0.6.2. Около 2 ГБ на диске под
три варианта модели.

## Как запустить

```bash
ollama pull qwen2.5:0.5b-instruct-q4_0
ollama pull qwen2.5:0.5b-instruct-q8_0
ollama pull qwen2.5:0.5b-instruct-fp16
python3 quant_bench.py
```

Подробности по шагам, ожидаемый вывод и что делать, если пошло не так, — в
[RUNBOOK.md](RUNBOOK.md).

## Что получилось на прогоне

| Тег | Размер | Тёплый вызов |
|---|---|---|
| `q4_0` | 335,9 МБ | 92,6 ток/с |
| `q8_0` | 506,5 МБ | 73,1 ток/с |
| `fp16` | 948,1 МБ | 51,1 ток/с |

4-битный вариант почти втрое компактнее fp16 и почти вдвое быстрее генерирует токены.
Неудобный результат: на модели такого масштаба (0.5B) разница в *качестве* ответа между
квантованиями почти не видна — сама модель слабо объясняет термин независимо от разрядности,
у неё просто не хватает параметров для содержательного ответа на этот вопрос. Демонстрирует
компромисс по размеру и скорости, но не годится для демонстрации потери точности — для этого
нужна модель заметно крупнее.
