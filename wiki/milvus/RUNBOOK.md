# RUNBOOK: Milvus Lite — коллекция, HNSW-индекс, ANN-поиск

## Окружение

- Python 3.12+
- `pymilvus[milvus_lite]==2.6.16` (тянет `milvus-lite` 3.2.1)
- Локальный Ollama (http://localhost:11434) с моделью `nomic-embed-text` для embeddings
- Docker не нужен — Milvus Lite работает как встраиваемая библиотека, база хранится в локальном
  файле

Установка:

```bash
python3 -m venv .venv
./.venv/bin/python3 -m pip install "pymilvus[milvus_lite]==2.6.16" ollama
```

Модель эмбеддингов должна быть скачана заранее:

```bash
ollama pull nomic-embed-text
```

## Шаг 1. Создать коллекцию и наполнить её

```bash
./.venv/bin/python3 collection_setup.py
```

Что происходит: скрипт поднимает Milvus Lite (файл `milvus_demo.db` в текущей папке), создаёт
коллекцию `tech_articles` с полями `id`, `vector` (768 измерений), `category` и `text`, считает
embeddings для 8 коротких документов через Ollama и строит HNSW-индекс.

Ожидаемый вывод:

```
вставлено документов: 8
индекс построен, коллекция загружена для поиска
```

Если вывода нет или скрипт падает на подключении к Ollama — Ollama не запущена, поднимите её
отдельно (`ollama serve`) и проверьте `curl http://localhost:11434/api/tags`.

## Шаг 2. Выполнить поиск

```bash
./.venv/bin/python3 search_demo.py
```

Что происходит: скрипт заново подключается к тому же файлу `milvus_demo.db`, повторно загружает
коллекцию в память и выполняет два поиска — обычный ANN-поиск по всей коллекции и поиск с
фильтром по скалярному полю `category`.

Ожидаемый вывод — список найденных документов с `distance` (чем ближе к 1.0 при метрике
COSINE, тем ближе документ к запросу по смыслу), у второго поиска все результаты только с
`category == 'orchestration'`.

## Если не так

- **`Collection '...' is in state 'released'`** — коллекция Milvus Lite не сохраняет состояние
  загрузки между процессами. Каждое новое подключение к файлу базы должно само вызвать
  `load_collection()` перед поиском (в `search_demo.py` это уже сделано).
- **`ollama api: НЕДОСТУПНА` / ошибка подключения к порту 11434** — сервер Ollama не поднят,
  запустите `ollama serve` в отдельном терминале.
- **Разные числа `distance` при повторном запуске** — нормально: Ollama возвращает
  детерминированные embeddings для одного и того же текста, но при повторной вставке документов
  (`rm -rf milvus_demo.db` перед `collection_setup.py`) порядковые `id` и порядок в индексе HNSW
  могут отличаться от прошлого прогона.
- **Файл `milvus_demo.db` — это каталог, а не файл** — так и должно быть, Milvus Lite хранит
  данные в виде директории с внутренними файлами. Удаляется как обычная папка (`rm -rf`).
