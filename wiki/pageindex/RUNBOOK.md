# RUNBOOK: PageIndex, дерево документа и reasoning-поиск по нему

Прогон двух демо к статье про PageIndex. Первое строит дерево из PDF вообще без модели,
второе ищет ответ по этому дереву локальной LLM.

## Окружение

| Компонент | Версия |
|---|---|
| Python | 3.12 или новее (проверено на 3.12.13) |
| pageindex | 0.2.10 |
| litellm | 1.98.0 |
| pypdfium2 | 5.12.1 |
| Ollama | 0.32.13, доступна на http://localhost:11434 |
| Модель | qwen2.5:7b |

Нужен PDF на несколько десятков страниц со внятной структурой. В примере это усечённый годовой
отчёт Федеральной резервной системы из репозитория PageIndex, файл `annual_report.pdf` рядом со
скриптами. Подойдёт любой похожий документ, поменяйте имя файла в обоих скриптах.

## Шаг 1. Поставить зависимости

```bash
python3 -m venv .venv
./.venv/bin/python3 -m pip install pageindex litellm pypdfium2
```

Проверка: команда `./.venv/bin/pip list | grep pageindex` печатает строку с версией 0.2.10.

## Шаг 2. Проверить, что Ollama жива и модель на месте

```bash
ollama --version
ollama list | grep qwen2.5
curl -s -m 5 http://localhost:11434/api/tags
```

Проверка: последняя команда отдаёт JSON со списком моделей. Если ответа нет, поднимите сервер
командой `ollama serve` в отдельном окне. Модель качается командой `ollama pull qwen2.5:7b`.

## Шаг 3. Построить дерево документа

```bash
./.venv/bin/python3 build_tree.py
```

Что должно быть в выводе: заголовок документа, время построения в пределах нескольких секунд,
дерево с отступами и диапазонами страниц, файл `tree.json` рядом со скриптом. Строка про
отсутствие вызовов LLM не рекламная: параметры `summary=False` и `optimize=False` действительно
отключают обращения к модели, и шаг работает без всяких ключей.

## Шаг 4. Найти ответ через дерево

```bash
./.venv/bin/python3 tree_search.py
```

Что должно быть в выводе: JSON с выбранным узлом и причиной выбора, путь к узлу от корня,
диапазон страниц, размер текста, ушедшего в контекст, и ответ на вопрос. На вопрос про надзор за
криптоактивами модель выбирает узел с заголовком Crypto-Asset Supervision.

## Если не так

- **Модель отвечает не JSON, скрипт падает на разборе.** Мелкие модели иногда добавляют текст
  вокруг JSON. Регулярное выражение в скрипте это переживает, но если формат уехал совсем,
  повторите запуск или возьмите модель покрупнее.
- **Первый вызов идёт минуту и дольше.** Ollama грузит модель в память при первом обращении.
  Второй и последующие вызовы укладываются в секунды.
- **Таймаут соединения на 600 секунд.** Так выглядит очередь: локальный сервер выполняет запросы
  по одному. В демо запросы идут последовательно, поэтому очереди не возникает.
- **Дерево получилось плоским или пустым.** Режим flash читает типографику страниц и закладки
  PDF. У сканированного документа без текстового слоя брать структуру неоткуда, тут нужен режим
  standard, который строит её моделью.
