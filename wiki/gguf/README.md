# GGUF

Код к статье [GGUF](https://bigdataschool.ru/wiki/gguf/).

Разбор GGUF-файла модели, которую Ollama уже скачала на диск: заголовок, метаданные
ключ-значение, описания тензоров и выравнивание, а затем подсчёт того, из каких типов
квантования на деле собраны файлы `q4_0` и `q8_0` одной модели. Модель не запускается,
читается только файл, GPU не нужен.

## Состав

| Файл | Что внутри |
|---|---|
| `gguf_file_anatomy.py` | находит GGUF-файл тега в хранилище Ollama, читает 24 байта заголовка через `struct`, затем весь файл через `gguf.GGUFReader`: метаданные, `general.file_type`, первые тензоры, проверка выравнивания |
| `gguf_quant_mix.py` | по каждому тегу считает тензоры, веса и бит на вес в разрезе типов квантования и перечисляет тензоры не основного типа |
| `docker-compose.yml` | Ollama в Docker с каталогом моделей на хосте, если Ollama не установлена локально |
| `RUNBOOK.md` | пошаговая инструкция с ожидаемым выводом и разбором типовых граблей |

## Окружение

Python 3.12, пакет `gguf` 0.19.0 (тянет `numpy`), Ollama 0.40.13. Около 900 МБ на диске под
две модели. Прогнано на Ubuntu 24.04 x86_64, Ollama в Docker.

## Как запустить

```bash
ollama pull qwen2.5:0.5b-instruct-q4_0
ollama pull qwen2.5:0.5b-instruct-q8_0
python3 -m venv .venv && .venv/bin/pip install gguf==0.19.0
# путь к каталогу моделей Ollama, если он не ~/.ollama/models
export OLLAMA_MODELS=~/.ollama/models
.venv/bin/python gguf_file_anatomy.py qwen2.5:0.5b-instruct-q4_0
.venv/bin/python gguf_quant_mix.py qwen2.5:0.5b-instruct-q4_0 qwen2.5:0.5b-instruct-q8_0
```

Подробности по шагам, ожидаемый вывод и что делать, если пошло не так, в
[RUNBOOK.md](RUNBOOK.md).

## Что получилось на прогоне

| Тег | Размер файла | Тензоры по типам | Бит на вес в среднем |
|---|---|---|---|
| `q4_0` | 335,8 МиБ | 168 Q4_0, 1 Q8_0, 121 F32 | 5,61 |
| `q8_0` | 506,5 МиБ | 169 Q8_0, 121 F32 | 8,50 |

Файл с суффиксом Q4_0 собран из Q4_0 не целиком. Матрица эмбеддингов `token_embd.weight`
(136 млн весов из 494 млн, 27,6%) лежит в Q8_0, а нормы и bias-тензоры внимания в F32. Отсюда
средние 5,61 бита на вес вместо 4,5 у самого типа Q4_0. Отдельного тензора `output.weight` в
файле нет: у Qwen2.5 0.5B выходной слой делит веса с эмбеддингами.
