# LoRA (Low-Rank Adaptation)

Код к статье [LoRA (Low-Rank Adaptation)](https://bigdataschool.ru/wiki/lora/).

Два независимых демо на базовой модели Qwen2.5-0.5B-Instruct: как ранг LoRA влияет на число
обучаемых параметров и размер адаптера, и что даёт `merge_and_unload()` для задержки
инференса. Всё считается локально на MPS (Apple Silicon), видеокарта NVIDIA не нужна.

## Состав

| Файл | Что внутри |
|---|---|
| `rank_ablation.py` | LoraConfig для r=4/8/32 на одних target_modules, число обучаемых параметров и размер адаптера на диске для каждого ранга |
| `merge_latency.py` | короткое дообучение адаптера r=8, замер задержки генерации до и после `merge_and_unload()` |
| `requirements.txt` | версии пакетов, зафиксированные по факту прогона |
| `RUNBOOK.md` | пошаговая инструкция с ожидаемым выводом и разбором типовых граблей |

## Окружение

macOS 26.5.2 (arm64), Python 3.12.13, torch 2.13.0, transformers 5.15.1, peft 0.20.0.
Около 1 ГБ на диске под веса базовой модели.

## Как запустить

```bash
python3.12 -m venv .venv
./.venv/bin/python3 -m pip install -r requirements.txt
./.venv/bin/python3 rank_ablation.py
./.venv/bin/python3 merge_latency.py
```

Подробности по шагам, ожидаемый вывод и что делать, если пошло не так, — в
[RUNBOOK.md](RUNBOOK.md).

## Что получилось на прогоне

Обучаемых параметров: 540 672 при r=4, 1 081 344 при r=8, 4 325 376 при r=32 — рост ровно
пропорционален рангу. Адаптер на диске: 2.1 МБ, 4.2 МБ, 17 МБ соответственно.

Пять эпох дообучения на восьми примерах заняли 7.1 с. Генерация с не слитым адаптером — 1.859 с
в среднем по 10 прогонам, после `merge_and_unload()` — 1.811 с, ускорение всего 1.03x: на
модели такого масштаба и с KV-кэшем при генерации выигрыш от слияния почти не заметен,
основное время съедает не лишний матричный проход адаптера, а сама авторегрессивная генерация
токен за токеном.
