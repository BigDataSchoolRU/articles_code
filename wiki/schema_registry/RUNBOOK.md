# RUNBOOK: Schema Registry на локальном стенде

Пошаговый прогон примеров из статьи. После каждого шага указано, что должно быть в выводе.

## Окружение

- Docker с Compose, образы `apache/kafka:4.3.0` и `confluentinc/cp-schema-registry:8.3.1`
- Python 3.12, пакет `confluent-kafka` 2.15.0 с дополнениями `avro` и `schemaregistry`
- Свободные порты 9092 (брокер) и 8081 (реестр)

Установка Python-зависимостей:

```
pip install "confluent-kafka[avro,schemaregistry]"
```

## Шаг 1. Поднять брокер и реестр

```
docker compose up -d
```

Проверка: `docker ps` показывает два контейнера в состоянии Up. Реестру нужно около 20 секунд
на старт, готовность проверяется запросом списка subject:

```
curl -s http://localhost:8081/subjects
```

Должно вернуться `[]` на чистом стенде. Ответ `curl: (7) Failed to connect` означает, что реестр
ещё поднимается, повторите через несколько секунд.

## Шаг 2. Проверить версию реестра

```
curl -s http://localhost:8081/v1/metadata/version
```

В выводе версия и идентификатор коммита сборки, например `{"version":"8.3.1",...}`.

## Шаг 3. Зарегистрировать схему и проверить совместимость

```
./compat_check.sh
```

Что должно быть в выводе по порядку:

- ответ с полями `id`, `version` и `guid` — первая версия схемы зарегистрирована
- `{"is_compatible":true}` — поле со значением по умолчанию проходит проверку
- `{"is_compatible":false}` — то же поле без значения по умолчанию отвергнуто
- ответ с `"version":2` — совместимая версия зарегистрирована
- `{"compatibilityLevel":"BACKWARD"}` — уровень проверки по умолчанию

Скрипт начинается с удаления subject, поэтому его можно гонять повторно. Идентификаторы схем
при этом растут: реестр не переиспользует номера удалённых схем.

## Шаг 4. Посмотреть на формат сообщения

```
python3 avro_roundtrip.py
```

В выводе длина сообщения в байтах, префикс в шестнадцатеричном виде, номер схемы и прочитанная
обратно запись. Первый байт префикса нулевой, следующие четыре содержат идентификатор схемы.

## Шаг 5. Прибрать за собой

```
docker compose down
```

## Если не так

- **Порт занят.** Проверьте, что на 9092 и 8081 не висят другие контейнеры: `docker ps`.
- **Реестр не стартует.** Смотрите логи: `docker compose logs schema-registry | tail -30`.
  Частая причина — брокер ещё не поднялся, реестр перезапускается сам.
- **Python не видит модуль confluent_kafka.** Пакет поставлен в другое окружение, проверьте
  тем же интерпретатором: `python3 -c "import confluent_kafka; print(confluent_kafka.version())"`.
- **`is_compatible` возвращает не то, что в статье.** В subject остались версии от прошлых
  прогонов. Скрипт чистит subject сам, но если вы гоняли запросы руками, удалите subject:
  `curl -X DELETE "http://localhost:8081/subjects/orders-value?permanent=true"`.
