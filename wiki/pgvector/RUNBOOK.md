# RUNBOOK: pgvector — векторный поиск внутри PostgreSQL

Демо поднимает векторный поиск (ANN) и гибридный запрос с фильтром прямо в PostgreSQL,
без внешнего векторного хранилища.

## Окружение

- PostgreSQL 14 или новее (демо прогонялось на 18.4), доступ с правами на `CREATE EXTENSION`
  и `CREATE DATABASE`.
- Расширение `pgvector` 0.8.0 или новее (демо прогонялось на 0.8.6) — HNSW-параметры
  `hnsw.iterative_scan` появились именно в 0.8.0, на более старой версии шаг 4 работать не будет.
- Клиент `psql` в `PATH`.
- Замените адреса и имя базы на свои, если подключаетесь не к локальному серверу.

## Шаг 0. Установка расширения

Если `pgvector` ещё не собран для вашей установки PostgreSQL, поставьте его через пакетный
менеджер (пример для Homebrew на macOS):

```bash
brew install pgvector
```

Для других ОС — сборка из исходников или системный пакет, инструкция в
[официальном README](https://github.com/pgvector/pgvector#installation).

## Шаг 1. База и таблица

```bash
createdb pgvector_demo
psql -d pgvector_demo -f setup.sql
```

Ожидаемый вывод: `CREATE EXTENSION`, `CREATE FUNCTION`, `CREATE TABLE`, `INSERT 0 5000`, затем
две таблицы — по 250 строк в категории `niche` и 4750 в `popular`, и `distinct_vectors = 5000`
(все векторы разные — если увидите число сильно меньше 5000, смотрите раздел «если не так»).

## Шаг 2. Индекс HNSW

```bash
psql -d pgvector_demo -f hnsw_index.sql
```

Ожидаемый вывод: `CREATE INDEX`, дальше описание таблицы со строкой индекса
`documents_embedding_idx" hnsw (embedding vector_cosine_ops) ...`.

## Шаг 3. Обычный ANN-запрос

```bash
psql -d pgvector_demo -f ann_query.sql
```

В плане запроса (`EXPLAIN`) должна быть строка `Index Scan using documents_embedding_idx` —
значит, поиск идёт через HNSW, а не полным перебором. Ниже — пятёрка ближайших к случайному
вектору строк с расстоянием (значения будут другими при каждом прогоне, вектор запроса
генерируется заново).

## Шаг 4. Гибридный запрос и overfiltering

```bash
psql -d pgvector_demo -f hybrid_query.sql
```

Запрос ищет 20 ближайших строк в редкой категории `niche` (5% таблицы) сначала с
`hnsw.iterative_scan = off`, потом с `relaxed_order`. Ожидаемая картина: первый запрос
возвращает заметно меньше 20 строк (в наших прогонах 3-4), второй — ровно 20. Это и есть
overfiltering: ANN-индекс находит кандидатов по близости вектора, а `WHERE`-фильтр
отбрасывает часть уже после сканирования.

Файл сам включает `enable_seqscan = off` перед демонстрацией — на таблице в 5000 строк
планировщик PostgreSQL и без принуждения выбирает точный перебор для такого избирательного
фильтра (см. следующий раздел), и без этой команды разницы между `off` и `relaxed_order`
видно не будет вообще.

## Если не так

- **`distinct_vectors` заметно меньше 5000.** Функция генерации вектора объявлена без
  `VOLATILE` или переписана как некоррелированный подзапрос вида
  `(SELECT ... FROM generate_series(...))`. PostgreSQL вправе вычислить такой подзапрос
  один раз на весь запрос и подставить одно и то же значение во все строки — ловушка,
  на которую наткнулись при подготовке этого демо. Генерация значения должна идти через
  обычный вызов volatile-функции в списке колонок, а не через подзапрос.
- **`EXPLAIN` в шаге 3 или 4 показывает `Seq Scan` вместо `Index Scan`, хотя вы не трогали
  `enable_seqscan`.** На маленьких таблицах (в демо — 5000 строк) планировщик PostgreSQL
  по стоимости сам решает, что перебор дешевле обращения к HNSW-индексу, особенно когда
  фильтр отсекает большую часть строк. Это штатное поведение планировщика, а не поломка;
  на таблице промышленного размера (сотни тысяч и больше строк) он сам выбирает индекс.
  Файл `hybrid_query.sql` форсирует индекс через `enable_seqscan = off` намеренно, только
  для демонстрации — в проде эту настройку менять не нужно.
- **`ERROR: type "vector" does not exist`.** Расширение не создано в текущей базе данных —
  `CREATE EXTENSION` действует на одну базу, а не на весь сервер. Проверьте, что
  подключились к `pgvector_demo`, а не к `postgres`.
- **`hnsw.iterative_scan` не распознаётся как параметр.** Версия расширения старше 0.8.0.
  Проверить версию: `SELECT extversion FROM pg_extension WHERE extname = 'vector';`.
