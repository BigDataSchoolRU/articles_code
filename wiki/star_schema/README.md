# Star schema

Код к статье [Star schema](https://bigdataschool.ru/wiki/star_schema/).

Одна и та же модель продаж в PostgreSQL 18.6 в двух вариантах. Star schema держит таблицу фактов
`fact_sales` на 2 млн строк и четыре денормализованных измерения: дату, товар, магазин и
покупателя. Snowflake schema строится из неё и выносит иерархии товар → подкатегория → категория
и магазин → город → регион в отдельные справочники. На обеих схемах выполняется одна бизнес-выборка
«выручка по категории и региону за II квартал 2025». Сравниваются результат (md5 всех строк),
число JOIN в плане, время планирования и выполнения, порядок JOIN при `join_collapse_limit`,
удаление лишнего LEFT JOIN и цена переименования категории.

## Состав

| Файл | Что делает |
|---|---|
| `docker-compose.yml` | PostgreSQL 18.6 в Docker, порт `127.0.0.1:55439`, `shared_buffers=256MB`, SQL-сценарии смонтированы в `/demo/sql` |
| `star_schema_demo.sh` | запускает шаги по очереди или по одному: `all`, `star`, `snowflake`, `queries`, `rename` |
| `sql/01_star.sql` | схема `star`: `dim_date`, `dim_product`, `dim_store`, `dim_customer` и `fact_sales` на 2 млн строк, данные от `setseed(0.42)` |
| `sql/02_snowflake.sql` | схема `snowflake` из тех же данных: шесть справочников вместо двух измерений, копия факта, размеры таблиц |
| `sql/03_queries.sql` | выборка на двух схемах: совпадение результата, `EXPLAIN (ANALYZE, BUFFERS)`, медианы по 5 прогонам, `join_collapse_limit = 1`, удаление LEFT JOIN |
| `sql/04_rename.sql` | переименование категории: сколько строк меняет `UPDATE` и сколько WAL пишет каждая схема |
| `RUNBOOK.md` | пошаговый прогон с ожидаемым выводом |

## Окружение

Docker с плагином Compose и образ `postgres:18.6`. Python не нужен: данные генерируются в SQL, а
сценарии идут через `psql` внутри контейнера. Нужно около 300 МБ на диске под том.

## Как запустить

```bash
docker compose up -d --wait
./star_schema_demo.sh all
docker compose down -v
```

Весь прогон идёт около 40 секунд, из них примерно 20 уходят на загрузку данных.
