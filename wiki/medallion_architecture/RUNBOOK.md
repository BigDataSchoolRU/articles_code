# RUNBOOK: медальонная архитектура на DuckDB (Bronze / Silver / Gold)

Демо показывает механику медальонной архитектуры на одном локальном файле DuckDB: сырой приём
заказов в Bronze, идемпотентный upsert в Silver через `MERGE INTO`, полный пересчёт витрины в
Gold. Никакой внешней инфраструктуры не требуется.

## Окружение

- Python 3.12+
- `duckdb` 1.5.5. Оператор `MERGE INTO` доступен начиная с DuckDB 1.4.0 LTS, версия 1.5.5
  зафиксирована по стенду, на котором прогонялось демо

Установка:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install duckdb==1.5.5
```

## Шаг 1. Запуск демо

```bash
python3 bronze_silver_gold_demo.py
```

Скрипт создаёт файл `medallion_demo.duckdb` в текущей папке (можно удалить и перезапустить — все
таблицы пересоздаются с нуля каждый прогон).

## Шаг 2. Что должно быть в выводе

Первый батч (5 строк, из них один дубль заказа и две невалидные строки):

```
=== батч 1: ингест в Bronze ===
Bronze строк: 5

=== батч 1: первый прогон Bronze -> Silver ===
Отклонено строк: 2 [('ORD-1003', None, '45.00'), ('ORD-1004', 'CUST-3', 'not_a_number')]
Silver строк после первого прогона: 2
```

Если строк не 5 в Bronze или не 2 в Silver — проверьте, что тестовые данные в `main()` не
менялись.

## Шаг 3. Идемпотентность Bronze -> Silver

Скрипт сам вызывает трансформацию батча 1 второй раз подряд и печатает:

```
=== батч 1: повторный прогон той же трансформации (идемпотентность) ===
Silver строк после повторного прогона: 2
```

Число строк должно совпасть с шагом 2. Это и есть идемпотентность: повторный прогон одного и
того же батча не создаёт дублей, потому что `MERGE INTO` работает по естественному ключу
`order_id`, а не добавляет строки слепым `INSERT`.

## Шаг 4. Инкремент вторым батчом

Второй батч содержит исправление цены по существующему заказу и один новый заказ:

```
=== батч 2: исправление цены + новый заказ ===
Silver строк после батча 2: 3
Цена ORD-1001 после апдейта: (Decimal('119.90'), datetime.date(2026, 8, 21))
```

Строк должно стать на 1 больше, а у исправленного заказа — новая цена.

## Шаг 5. Gold как пересчёт, а не докатка

```
=== Silver -> Gold: полный пересчёт витрины ===
order_date    category  revenue  orders_count
2026-08-20       books    18.50             1
2026-08-21       books     9.99             1
2026-08-21 electronics   119.90             1
```

Повторный вызов пересчёта Gold без изменений в Silver должен вернуть то же число строк —
`CREATE OR REPLACE TABLE` идемпотентен по построению, в отличие от инкрементального добавления.

## Если не так

- **`Catalog Error: MERGE INTO`** или синтаксическая ошибка на `MERGE` - версия DuckDB старше
  1.4.0, обновите пакет: `pip install -U duckdb`.
- **Silver строк больше 2 после первого прогона** — дедуп по `row_number() OVER (PARTITION BY
  order_id ORDER BY ingested_at DESC)` не сработал, скорее всего два прогона попали в один и тот
  же `ingested_at` (разрешение таймстампа): добавьте `sleep 1` между вызовами `ingest_bronze`,
  если правите тестовые данные.
- **`TRY_CAST` пропускает битую строку в Silver** — проверьте, что колонка `amount_raw` в Bronze
  осталась `VARCHAR`, а не была приведена к числу на этапе ингеста: типизация битой строки в число
  на INSERT замаскирует ошибку раньше, чем до неё дойдёт трансформация.
