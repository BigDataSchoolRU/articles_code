# RUNBOOK: Tool Calling на локальной модели через Ollama

Пошаговый прогон демо к Wiki-статье «Tool Calling». Всё работает локально, ключи и внешние
сервисы не нужны.

## Окружение

| Компонент | Версия |
|---|---|
| Python | 3.12.13 |
| ollama (python client) | 0.6.2 |
| pydantic | 2.13.4 |
| Ollama | 0.32.9 |
| Модель | qwen2.5:7b (4.7 ГБ) |

Что должно быть доступно: сервис Ollama на `http://localhost:11434` и скачанная модель с
поддержкой вызова инструментов. Если Ollama слушает другой адрес, подставьте свой в переменную
`host` в обоих скриптах.

## Шаг 1. Проверить, что Ollama жив

```bash
ollama --version
curl -s -m 5 http://localhost:11434/api/tags | head -c 200
```

Ожидаемо: печатается версия и JSON со списком моделей. Пустой ответ или отказ в соединении
означают, что сервис не запущен.

## Шаг 2. Скачать модель с поддержкой инструментов

```bash
ollama pull qwen2.5:7b
ollama list
```

Ожидаемо: в списке есть строка `qwen2.5:7b`. Модели без нативной поддержки инструментов на
этом демо будут отвечать текстом вместо `tool_calls`.

## Шаг 3. Поставить зависимости

```bash
python3 -m venv .venv
./.venv/bin/python3 -m pip install "ollama==0.6.2" "pydantic==2.13.4"
```

Ожидаемо: pip сообщает `Successfully installed`. Проверка: `./.venv/bin/python3 -c "import ollama, pydantic"` отрабатывает молча.

## Шаг 4. Прогнать агентный цикл

```bash
./.venv/bin/python3 tool_calling_demo.py
```

Ожидаемо: в первом сценарии модель делает два вызова подряд, `get_course_info` и следом
`calc_discount`, и только на третьем шаге отвечает текстом. Во втором сценарии вызовов нет,
ответ приходит сразу. Если модель зациклилась, её остановит предохранитель на пятом шаге.

## Шаг 5. Прогнать валидацию и замер токенов

```bash
./.venv/bin/python3 tool_calling_guard.py
```

Ожидаемо: три строки с результатами диспетчера (успех, отказ по имени, отказ по типу
аргумента) и три строки с `prompt_eval_count` для нуля, двух и десяти инструментов. Абсолютные
числа зависят от модели и шаблона промпта, важен порядок роста.

## Если не так

- **`ConnectError` или пустой ответ на шаге 1.** Сервис Ollama не запущен, поднимите его
  командой `ollama serve` в отдельном терминале.
- **Модель отвечает текстом вместо вызова инструмента.** Проверьте, что запущена именно модель
  с поддержкой tools, и что описания инструментов не пустые: решение принимается по описанию.
- **`TypeError` при вызове функции.** Модель вернула аргументы не того типа. Так и должно быть,
  для этого в `tool_calling_guard.py` стоит валидация до вызова.
- **Числа `prompt_eval_count` отличаются от приведённых.** Это нормально, у каждой модели свой
  шаблон промпта под инструменты.
