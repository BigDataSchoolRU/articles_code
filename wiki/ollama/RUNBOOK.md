# RUNBOOK: демо к статье про Ollama

## Окружение

- Ollama 0.32.13+ ([инструкции по установке](https://docs.ollama.com/quickstart)), сервер запущен
  (`ollama serve` или через приложение Ollama).
- Python 3.12+, пакет `ollama` (python-клиент) версии 0.6.2+: `pip install ollama`.
- Модели, скачанные заранее:
  ```bash
  ollama pull qwen2.5:7b
  ollama pull qwen2.5:0.5b-instruct-q4_0
  ollama pull qwen2.5:0.5b-instruct-q8_0
  ollama pull qwen2.5:0.5b-instruct-fp16
  ```
  Модель `qwen2.5:7b` занимает около 4.7 ГБ, три тега `qwen2.5:0.5b-instruct-*` вместе — около
  1.8 ГБ.
- Порт по умолчанию: `http://localhost:11434`. Проверка живости сервера:
  ```bash
  curl -s http://localhost:11434/api/tags
  ```
  Ответ — JSON со списком локальных моделей. Если сервер не отвечает, запустите `ollama serve`.

## Шаг 1. chat_tools.py — жизненный цикл запроса

```bash
python3 chat_tools.py
```

Что делает: обычный `chat` (полный ответ разом), потоковый `chat` (`stream=True`, ответ приходит
фрагментами) и вызов инструмента (tool calling) с заглушкой функции `get_weather`.

Ожидаемый вывод: три блока `[chat]`, `[stream]`, `[tools]`. В блоке `[tools]` видно, что модель
сначала возвращает структурированный вызов функции с аргументами, а связный текстовый ответ
приходит только вторым вызовом, после того как результат функции подставлен обратно в диалог.

Шаг прошёл, если в каждом блоке есть содержательный ответ модели и скрипт завершился без
трейсбека.

## Шаг 2. modelfile_quantization.py — Modelfile и метаданные квантования

```bash
python3 modelfile_quantization.py
```

Что делает: создаёт временную модель поверх `qwen2.5:0.5b-instruct-q4_0` с кастомным
system-промптом через `ollama.create()` (аналог `Modelfile`), проверяет её ответом, удаляет.
Затем читает метаданные (`quantization_level`, `parameter_size`, размер на диске) у трёх тегов
одной и той же модели с разным квантованием.

Ожидаемый вывод: блок `[modelfile]` с ответом временной модели и подтверждением удаления, затем
таблица `[quant]` из трёх строк — `q4_0`/`q8_0`/`fp16` с разными `quantization_level` и разным
размером на диске при одинаковом числе параметров.

Шаг прошёл, если таблица выведена полностью и скрипт завершился без ошибок.

## Если не так

- **`ConnectionError` / `Warning: could not connect to a running Ollama instance`** — сервер не
  запущен. Запустите `ollama serve` в отдельном терминале и повторите.
- **`ollama._types.ResponseError: model '...' not found`** — модель не скачана. Выполните
  `ollama pull <имя>` из списка в разделе «Окружение».
- **Скрипт из шага 2 падает на `ollama.create()` с ошибкой о существующей модели** — временная
  модель `wiki-ollama-demo` осталась от прерванного прогона. Удалите вручную:
  `ollama rm wiki-ollama-demo` и запустите снова.
- **Ответы модели непредсказуемы** (язык ответа, длина, точность) — это ожидаемое поведение
  небольших локальных моделей, а не баг демо. В статье это отмечено отдельно.
