# RUNBOOK: минимальный LLMOps-контур на локальной модели

Пошаговый прогон демо к статье «LLMOps». Всё работает на локальной модели через Ollama, внешние
API и ключи не нужны.

## Окружение

| Компонент | Версия при прогоне |
|---|---|
| macOS | 26.5.2 (arm64) |
| Python | 3.12.13 |
| ollama (python-клиент) | 0.6.2 |
| Ollama (сервер) | 0.32.9 |
| Модель по умолчанию | qwen2.5:7b |
| Контрольная модель | llama3.1:8b |

Должно быть доступно: запущенный сервер Ollama на `http://localhost:11434` и скачанная модель с
поддержкой чата. Если у вас другой адрес сервера, подставьте свой в переменную `OLLAMA_HOST`.

## Шаг 1. Проверить, что Ollama жива и модель на месте

```bash
ollama --version
curl -s -m 5 http://localhost:11434/api/tags | head -c 200
ollama list
```

Что должно быть в выводе: версия сервера, JSON со списком моделей и таблица, в которой есть
`qwen2.5:7b`. Если модели нет, скачайте её:

```bash
ollama pull qwen2.5:7b
```

Шаг прошёл, если `ollama list` показывает модель и её размер.

## Шаг 2. Поставить python-клиент

```bash
python3 -m venv .venv
./.venv/bin/python3 -m pip install --upgrade pip
./.venv/bin/python3 -m pip install "ollama==0.6.2"
./.venv/bin/python3 -m pip show ollama | grep -E '^(Name|Version)'
```

Шаг прошёл, если последняя команда печатает `Name: ollama` и `Version: 0.6.2`.

## Шаг 3. Одиночный вызов с трассировкой

```bash
./.venv/bin/python3 llm_trace.py
```

В консоль печатается JSON одного трейса. Проверьте, что в нём заполнены `prompt_version`,
`prompt_hash`, `latency_ms`, `tokens_in`, `tokens_out` и `cost_rub`, а в `output` лежит одно
слово `billing`. Рядом появился файл `traces.jsonl` с той же записью.

Шаг прошёл, если файл создан и в нём ровно одна строка:

```bash
wc -l traces.jsonl
```

## Шаг 4. Offline-eval двух версий промпта

```bash
./.venv/bin/python3 eval_run.py
```

Скрипт гоняет восемь кейсов на версии промпта v1, затем на v2, печатает построчный результат и
сводку. Ожидаемая картина: у v1 pass rate близок к нулю, потому что модель отвечает свободным
текстом, у v2 заметно выше, потому что промпт требует ровно одно слово из списка. В конце
печатается проба на недетерминированность: три вызова с одинаковым входом дают разные ответы.

Шаг прошёл, если в сводке есть обе строки, v1 и v2, и pass rate у v2 выше.

## Шаг 5. Прогнать тот же промпт на другой модели

```bash
LLMOPS_MODEL=llama3.1:8b ./.venv/bin/python3 eval_run.py
```

Модель берётся из переменной окружения, код при этом не меняется. Сравните pass rate и медианную
латентность с предыдущим прогоном: цифры разойдутся, хотя промпт тот же самый. Это и есть
причина, по которой eval-набор гоняют на каждую смену версии модели.

Шаг прошёл, если прогон отработал и сводка отличается от прогона на первой модели.

## Шаг 6. Посмотреть накопленные трейсы

```bash
wc -l traces.jsonl
tail -n 1 traces.jsonl
```

Каждая строка это отдельный вызов со всеми полями. Простейший разбор без дополнительных
инструментов:

```bash
python3 -c "import json;rows=[json.loads(l) for l in open('traces.jsonl')];print('вызовов:',len(rows),'| рублей:',round(sum(r['cost_rub'] for r in rows),3))"
```

Шаг прошёл, если печатается число вызовов и суммарная стоимость.

## Если не так

- **`ConnectError` или отказ соединения.** Сервер Ollama не запущен. Поднимите его командой
  `ollama serve` и повторите шаг 1.
- **`model not found`.** Модель не скачана. Выполните `ollama pull qwen2.5:7b`.
- **`ModuleNotFoundError: ollama`.** Скрипт запущен системным питоном, а не интерпретатором из
  виртуального окружения. Запускайте полным путём `./.venv/bin/python3`.
- **`AttributeError` на `prompt_eval_count`.** Стоит слишком старый клиент. Обновитесь до 0.6.2.
- **Все кейсы v2 упали.** Модель дописывает пояснения. Проверьте, что температура нулевая, и
  посмотрите поле `output` в `traces.jsonl`: там видно, что именно вернула модель.
- **Прогон идёт минутами.** Первый вызов после старта грузит веса модели в память. Повторный
  прогон заметно быстрее.
