# RUNBOOK: голая модель против модели в harness

## Окружение

| Что | Версия |
|---|---|
| Python | 3.12, только стандартная библиотека, venv не нужен |
| Ollama | 0.40.13, локальная установка или Docker из этой папки |
| Модели | `qwen2.5:7b` (4.7 ГБ, ID 845dbda0ea48), `llama3.1:8b` (4.9 ГБ, ID 46e0c10c039e) |

Обе модели поддерживают вызов инструментов в Ollama. GPU не обязателен: прогон ниже снят на
4 vCPU без GPU, генерация шла со скоростью 1.5-3.4 токена в секунду. На машине с GPU те же
шаги идут в десятки раз быстрее, цифры тестов от этого не меняются.

Адрес Ollama скрипты берут из `OLLAMA_URL`, по умолчанию `http://localhost:11434`.

## Шаг 1. Ollama и модели

Если Ollama стоит локально:

```bash
ollama pull qwen2.5:7b
ollama pull llama3.1:8b
ollama list
```

Если Ollama нет, её можно поднять в Docker из этой папки:

```bash
docker compose up -d
docker exec harness-ollama ollama pull qwen2.5:7b
docker exec harness-ollama ollama pull llama3.1:8b
docker exec harness-ollama ollama list
```

Шаг прошёл, если в списке есть обе модели:

```
NAME           ID              SIZE
llama3.1:8b    46e0c10c039e    4.9 GB
qwen2.5:7b     845dbda0ea48    4.7 GB
```

## Шаг 2. Задача и тесты

В `task/` лежат заготовка `duration.py` с описанием формата в docstring и 13 тестов. Убедитесь,
что тесты запускаются и падают на заготовке:

```bash
cd task && python3 -m unittest -q test_duration 2>&1 | tail -1; cd ..
```

Ожидаемо: `FAILED (errors=13)`, функция пока бросает `NotImplementedError`.

## Шаг 3. Голая модель

```bash
python3 bare.py qwen2.5:7b
```

Модель получает заготовку и тесты одним сообщением и отвечает один раз. Скрипт берёт последний
блок кода из ответа, кладёт его во временную копию задачи и прогоняет тесты. Результат к модели
не возвращается. Вывод на прогоне:

```
модель: qwen2.5:7b
вызовов модели: 1, время: 368.3 с
тестов прошло: 5 из 13
  ERROR: test_case_insensitive (test_duration.ParseDurationTest.test_case_insensitive)
  ERROR: test_combined (test_duration.ParseDurationTest.test_combined)
  ...
```

Прошли только пять тестов на ошибочный ввод: функция бросает `ValueError` и на правильных
строках тоже.

## Шаг 4. Та же модель в harness

```bash
python3 harness.py qwen2.5:7b
```

Каждая строка это один шаг модели: что она сделала, сколько тестов проходит после шага, сколько
шаг занял. Вывод на прогоне:

```
шаг 1 | read_file(duration.py) | тестов 0/0 | 153.6 с
шаг 2 | read_file(test_duration.py) | тестов 0/0 | 30.7 с
шаг 3 | правка duration.py | тестов 1/13 | 212.7 с
шаг 4 | правка duration.py | тестов 3/13 | 218.8 с
шаг 5 | повтор кода шага 4 | тестов 3/13 | 271.9 с
шаг 6 | правка duration.py | тестов 3/13 | 348.6 с
шаг 7 | повтор кода шага 6 | тестов 3/13 | 483.9 с
шаг 8 | правка duration.py | тестов 5/13 | 329.9 с
модель: qwen2.5:7b
шагов модели: 8 из 8, правок кода: 4, повторов кода: 2, вызовов инструментов: 2, пустых ответов: 0, отказов песочницы: 0, время: 2050.1 с
тестов прошло: 5 из 13
```

Что делает harness на каждом шаге:

- модель читает файлы инструментом `read_file`, только внутри временной копии задачи;
- новый `duration.py` модель присылает блоком кода в тексте, harness записывает его сам и сразу
  прогоняет тесты, итог и имена упавших тестов уходят модели следующим сообщением;
- если код совпадает с уже присланным (сравнение по AST, без учёта форматирования и
  комментариев), тесты не гоняются, а модель получает «этот код уже был, смени подход»;
- после каждого прогона тестов в `progress.md` дописывается строка, её harness печатает в конце.

Сырые ответы модели по шагам можно сохранить: `TRACE=trace.jsonl python3 harness.py qwen2.5:7b`.

## Шаг 5. Контрольная модель

```bash
python3 bare.py llama3.1:8b
python3 harness.py llama3.1:8b
```

Код не зависит от модели, меняется только аргумент. Вывод на прогоне:

```

вызовов модели: 1, время: 174.5 с
тестов прошло: 4 из 13

шаг 1 | read_file(duration.py) | тестов 0/0 | 242.4 с
шаг 2 | правка duration.py | тестов 6/13 | 135.6 с
шаг 3 | read_file(duration.py) | тестов 6/13 | 55.1 с
шаг 4 | правка duration.py | тестов 9/13 | 222.8 с
шаг 5 | read_file(duration.py) | тестов 9/13 | 77.1 с
шаг 6 | повтор кода шага 4 | тестов 9/13 | 289.8 с
шаг 7 | read_file(duration.py) | тестов 9/13 | 36.9 с
шаг 8 | повтор кода шага 4 | тестов 9/13 | 227.6 с
модель: llama3.1:8b
шагов модели: 8 из 8, правок кода: 2, повторов кода: 2, вызовов инструментов: 4, пустых ответов: 0, отказов песочницы: 0, время: 1287.3 с
тестов прошло: 9 из 13
```

Итог по двум моделям на прогоне:

| Модель | Голая модель | В harness | Повторов кода |
|---|---|---|---|
| qwen2.5:7b | 5 из 13 | 5 из 13 | 2 |
| llama3.1:8b | 4 из 13 | 9 из 13 | 2 |

У llama3.1:8b harness поднял результат с 4 до 9 тестов за две правки, дальше модель дважды
вернула тот же код. Остались четыре теста: регистр (`1H`), склеенные пары (`1h30m` дало 3600
вместо 5400), порядок и повтор единиц. Модель делит строку по пробелам и разбирает только
первую пару в каждом куске. У qwen2.5:7b проверка и детектор повторов вывели модель из петли,
но только до уровня голой модели: все её версии делили строку не на пары, и `float("1h30")`
падал. Проверка тестами показывает модели, что не так, а не как это исправить. Потолок задаёт
сама модель.

## Если не так

- **`HTTP Error 500` на втором скрипте подряд, в `dmesg` видно `oom-kill` с `llama-server`.**
  Ollama в Docker видит память хоста, а не лимит контейнера, и держит прошлую модель
  загруженной ещё 5 минут. Две модели по 5 ГБ не влезают в 10 ГБ. В `docker-compose.yml` уже
  стоит `OLLAMA_MAX_LOADED_MODELS: "1"`; если Ollama своя, задайте ту же переменную или
  выгрузите модель командой `ollama stop qwen2.5:7b` перед сменой.
- **Шаг с правкой приходит пустым: `content` пустой, `tool_calls` нет, при этом модель
  сгенерировала сотни токенов.** Так выглядит вызов инструмента, который Ollama не смогла
  разобрать: многострочный код внутри JSON-аргумента малые модели экранируют с ошибками, и
  вызов выбрасывается целиком без ошибки. Поэтому в `harness.py` нет инструмента записи файла,
  код идёт блоком в тексте. Если вернуть такой инструмент, ищите в трассе шаги с большим
  `eval_count` и пустым ответом.
- **Модель присылает один и тот же код шаг за шагом.** Это петля: тесты возвращают ту же
  ошибку, модель отвечает тем же кодом. Детектор в `harness.py` ловит повтор и просит сменить
  подход. Без него qwen2.5:7b на этой задаче шесть шагов подряд присылала одинаковый код.
- **Модель не слушает «без docstring» и переписывает описание целиком.** Это стоит времени, а
  не результата: на CPU шаг растёт до 5-9 минут. Потолок задан `num_predict` 900 токенов.
- **Цифры тестов отличаются от приведённых.** Сид и `temperature 0` делают прогон повторимым
  только на той же версии Ollama и той же сборке модели. Малые модели чувствительны к мелким
  правкам harness: на этой задаче пилотная версия (другая формулировка инструкции, первый
  блок кода вместо последнего, без потолка токенов) довела qwen2.5:7b до 11 из 13 за 5 шагов,
  а версия из этой папки без детектора петли дала 3 из 13.
- **`Connection refused`.** Ollama не запущена или слушает другой адрес, задайте
  `OLLAMA_URL=http://<адрес>:11434`.
