# Контекстное окно: как повторить замеры

Три коротких демо показывают, из чего складывается контекстное окно, что происходит с текстом,
который в него не поместился, и сколько стоит длинный вход. Всё гоняется локально, платных API
не нужно.

## Окружение

| Что | Версия при прогоне |
|---|---|
| macOS | 26.5.2, arm64 (Apple Silicon) |
| Python | 3.12.13 |
| Ollama | 0.32.13, адрес `http://localhost:11434` |
| Модель | `qwen2.5:7b` (около 4.7 ГБ) |
| tiktoken | 0.13.0 |
| ollama (python-клиент) | 0.6.2 |

Подойдёт любая машина с 16 ГБ памяти. На другой модели числа будут другими, но картина та же.
Адрес Ollama подставьте свой, если она слушает не на localhost.

## Шаг 0. Поставить зависимости и модель

```bash
python3 -m venv .venv
./.venv/bin/python3 -m pip install tiktoken ollama
ollama serve &          # если демон ещё не поднят
ollama pull qwen2.5:7b
```

Проверка: команда ниже должна вернуть json со списком моделей, в нём есть `qwen2.5:7b`.

```bash
curl -s http://localhost:11434/api/tags
```

Если ответа нет, Ollama не запущена. На macOS она не поднимается сама после перезагрузки.

## Шаг 1. Токены против символов

```bash
./.venv/bin/python3 01_tokens_vs_chars.py
```

Что должно быть в выводе: таблица из четырёх строк с колонкой «символов на токен» и разбор слова
«Контекстное» на отдельные токены. Английская строка даёт около 5 символов на токен, русская
около 2.7. Шаг прошёл, если соотношение плотностей в последней строке около 0.5.

## Шаг 2. Что не влезло в окно

```bash
./.venv/bin/python3 02_needle_overflow.py
```

Скрипт кладёт кодовое слово в начало длинного промпта и четыре раза задаёт один и тот же вопрос,
меняя только `num_ctx`. Занимает пару минут: каждая смена размера окна перезагружает модель.

Что должно быть в выводе: таблица, где при `num_ctx` 1024 и 2048 модель кодовое слово не находит
и отвечает про журнал регламентных работ, а при 4096 и 8192 отвечает верно. Колонка учтённых
токенов при этом упирается примерно в половину окна, пока промпт не влезает, и совпадает с полной
длиной промпта, когда влезает.

Шаг прошёл, если в колонке «иголка найдена» есть и «нет», и «да». Если везде «да», увеличьте
число единиц наполнителя в `build_prompt`, у вас промпт слишком короткий.

## Шаг 3. Сколько стоит длинный вход

```bash
./.venv/bin/python3 03_prefill_cost.py
```

Что должно быть в выводе: четыре строки с растущей длиной промпта и временем префилла, то есть
обработки входа до первого токена ответа. Время растёт медленнее длины: на этих масштабах узкое
место не в самом внимании, а в накладных расходах на вызов, поэтому пропускная способность
префилла с длиной входа улучшается.

Шаг прошёл, если время префилла в последней строке заметно больше, чем в первой.

## Если не так

- **`ConnectionError` на localhost:11434.** Ollama не запущена, поднимите `ollama serve`.
- **Первый вызов после смены `num_ctx` идёт около минуты.** Это перезагрузка модели с новым
  размером окна, а не зависание. В демо 3 поэтому есть отдельный прогревочный вызов.
- **Модель отвечает не по-русски.** У маленьких квантованных сборок это бывает, добавьте в
  промпт явное «отвечай по-русски» или возьмите модель покрупнее.
- **Числа времени скачут между запусками.** На ноутбуке это нормально: троттлинг и фоновая
  нагрузка. Смотрите на порядок величин и на соотношение строк, а не на абсолютные значения.
- **`num_ctx` больше, чем модель поддерживает.** Рантайм молча ограничит окно паспортным
  значением модели, ошибки не будет. Паспортное значение смотрится в `ollama show qwen2.5:7b`.
