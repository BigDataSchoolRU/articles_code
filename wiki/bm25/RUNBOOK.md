# RUNBOOK: BM25 на Python и SQLite FTS5

Пошаговый прогон демо к статье [BM25](https://bigdataschool.ru/wiki/bm25/). Четыре скрипта
на одном корпусе из 16 русских документов: формула руками против библиотек, влияние `k1` и `b`,
стемминг русского текста, BM25 внутри SQLite FTS5.

## Окружение

| Компонент | Версия |
|---|---|
| Python | 3.12 или новее (этого требует numpy 2.5.4), проверено на 3.12.3 |
| rank-bm25 | 0.2.2 |
| bm25s | 0.3.16, без scipy: в этой версии тянет только numpy |
| PyStemmer | 3.1.0 (Snowball, стеммер `russian`) |
| numpy | 2.5.4 |
| SQLite | модуль `sqlite3` из стандартной библиотеки с FTS5, проверено на SQLite 3.45.1 |
| Железо | любое, проверено на 4 vCPU x86_64, Ubuntu 24.04 |

Внешние сервисы, Docker и GPU не нужны. Вывод детерминирован: оценки совпадут с приведёнными
ниже до последнего знака, кроме разницы порядка `1e-07` у bm25s, которая зависит от float32.

## Шаг 1. Окружение Python

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m pip list | grep -Ei "^(rank-bm25|bm25s|PyStemmer|numpy) "
.venv/bin/python -c "import sqlite3; print(sqlite3.sqlite_version)"
```

Ожидаемо: четыре строки `bm25s 0.3.16`, `numpy 2.5.4`, `PyStemmer 3.1.0`, `rank-bm25 0.2.2`
и версия SQLite. venv занимает около 90 МБ.

## Шаг 2. Формула руками против библиотек

```bash
.venv/bin/python 01_formula_by_hand.py
```

Скрипт считает BM25 на чистом Python тремя способами и сравнивает с библиотеками на той же
токенизации, при `k1=1.2`, `b=0.75`. Ожидаемо в начале:

```
Умолчания библиотек (inspect.signature):
  rank_bm25.BM25Okapi(self, corpus, tokenizer=None, k1=1.5, b=0.75, epsilon=0.25)
  bm25s.BM25: k1=1.5, b=0.75, method='lucene'
Корпус: N=16 документов, avgdl=21.062 токена, словарь 220 слов
k1=1.2, b=0.75; floor rank-bm25 для отрицательного IDF = 0.25 * средний IDF = 0.5470

=== 1. Формула руками против библиотек, max |разница| по 4 запросам x 16 документам ===
rank-bm25 BM25Okapi    2.66e-15
bm25s lucene           1.27e-07
bm25s robertson        1.29e-07
```

Шаг прошёл, если все три разницы меньше `1e-06`. Обе библиотеки по умолчанию берут `k1=1.5`, а
не `1.2`, как Lucene и Elasticsearch, поэтому `k1` задаётся явно.

Дальше идёт разбор оценки первого документа по словам: `tf`, `df`, IDF, частотная часть и вклад
каждого слова, сумма совпадает с bm25s (`2.5477`). Последний блок показывает топ-5 одних и тех
же документов в трёх вариантах:

```
=== 3. Топ-5 по запросу «хранилище и данные» ===
   слово «хранилище»: df=3, IDF Робертсона=+1.3499, IDF Lucene=1.5805
   слово «и»: df=13, IDF Робертсона=-1.3499, IDF Lucene=0.2305
   слово «данные»: df=4, IDF Робертсона=+1.0217, IDF Lucene=1.3291
rank-bm25 BM25Okapi    d7:3.867  d6:2.980  d12:2.220  d5:1.668  d4:1.571
bm25s lucene           d7:1.912  d6:1.457  d12:0.914  d5:0.754  d4:0.710
bm25s robertson        d7:1.470  d6:1.101  d12:0.652  d5:0.494  d4:0.465
```

Слово «и» встречается в 13 документах из 16, классический IDF у него отрицательный. Три
реализации лечат это по-разному: rank-bm25 подставляет `0.25 * средний IDF`, bm25s `robertson`
обрезает до нуля, Lucene добавляет единицу под логарифм. Числа разные, сравнивать между
библиотеками можно порядок, а не оценки.

## Шаг 3. Параметры k1 и b

```bash
.venv/bin/python 02_k1_b_effect.py
```

Первая таблица показывает насыщение: частотная часть `tf / (tf + k1)` при длине, равной
средней, не растёт выше 1.0. При `k1=1.2` десятое вхождение слова даёт `0.893`, двадцатое
`0.943`. Дальше идёт сетка `k1` x `b` по запросу «индекс». Ожидаемо:

```
k1=1.2  b=0.0   d2:0.806  d0:0.705  d1:0.705  d9:0.513  d11:0.513
k1=1.2  b=0.75  d0:0.688  d1:0.670  d2:0.643  d9:0.545  d11:0.534
```

`d2` это длинный обзор (46 токенов при среднем 21), слово «индекс» в нём трижды. Без поправки
на длину (`b=0`) он первый, при `b=0.75` уступает двум коротким документам, где слово стоит
дважды. При `b=0` документы с одинаковым `tf` получают одинаковую оценку, длину формула не видит.

## Шаг 4. Русский текст и стемминг

```bash
.venv/bin/python 03_russian_stemming.py
```

Ожидаемо для запроса «индексом ускорить поиск»:

```
без стемминга: токены запроса ['индексом', 'ускорить', 'поиск'], найдены в словаре ['поиск']
   d8  Векторный поиск                    0.732
...
Snowball russian: токены запроса ['индекс', 'ускор', 'поиск'], найдены в словаре ['индекс', 'поиск']
   d1  B-дерево в PostgreSQL              1.412
```

Без стемминга словоформа «индексом» в корпусе не встречается ни разу, и BM25 ищет только по
слову «поиск». После стемминга «индексом», «индекса» и «индексы» сходятся в основу «индекс».
Стеммер работает по правилам, а не по словарю: «ускорить» он режет до «ускор», а «ускоряет»
до «ускоря», и эти формы так и не совпадают.

## Шаг 5. BM25 в SQLite FTS5

```bash
.venv/bin/python 04_sqlite_fts5.py
```

Ожидаемо:

```
SQLite 3.45.1

=== Запрос «инвертированный индекс для поиска», MATCH '"инвертированный" OR "индекс" OR "для" OR "поиска"' ===
d0  Инвертированный индекс             bm25()=-4.645689  формула=-4.645689  разница=0.0e+00
...
Запрос «инвертированный индекс для поиска»: через пробел (AND) найдено 0 документов, через OR 6
rank = bm25(docs) в 6 строках из 6
```

`bm25()` возвращает оценку со знаком минус, чтобы `ORDER BY bm25(docs)` по возрастанию ставил
лучшее совпадение первым. Поле `формула=` считает то же на Python по исходнику
`ext/fts5/fts5_aux.c`: IDF Робертсона, неположительный IDF заменяется на `1e-6`, `k1=1.2` и
`b=0.75` зашиты в код, длина документа считается по всем колонкам. Слова через пробел в `MATCH`
означают AND, поэтому для ранжирования «по любому слову» запрос собирается через `OR`.

В последнем блоке `bm25(docs, 10.0, 1.0)` даёт попаданию в заголовок вес десяти попаданий в
текст, и документ со словом в заголовке поднимается с `-0.989` до `-1.453`.

## Если не так

- `sqlite3.OperationalError: no such module: fts5`: ваш Python собран с SQLite без FTS5.
  Поставьте Python из пакетного менеджера ОС или из Homebrew, либо пропустите шаг 5.
- `ModuleNotFoundError: No module named 'corpus'`: скрипт запущен не из этой папки, перейдите в
  неё (`cd`) и повторите.
- Оценки bm25s расходятся с формулой в седьмом знаке: это float32 внутри bm25s, норма. Если
  расходятся в первом, проверьте, что `k1` и `b` заданы явно: умолчание у bm25s и rank-bm25
  `k1=1.5`.
- pip не находит `numpy==2.5.4`: версия Python ниже 3.12, создайте venv на 3.12 или новее.
