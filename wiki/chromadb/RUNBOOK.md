# ChromaDB: поднять коллекцию с локальными эмбеддингами

Демо к статье [ChromaDB](https://bigdataschool.ru/wiki/chromadb/).
Вся векторизация идёт через локальную Ollama, ключи и платные API не нужны.

## Окружение

| Что | Версия |
|---|---|
| Python | 3.12 или новее (Chroma требует >= 3.9) |
| chromadb | 1.5.9 |
| Ollama | 0.32.13 |
| Модель эмбеддингов | nomic-embed-text, 768 измерений, около 274 МБ |

Адрес Ollama в скриптах задан как `http://localhost:11434`. Если ваш сервер живёт на другом
хосте или порту, поправьте константу `OLLAMA_URL` в обоих файлах.

## Шаг 1. Поставить зависимости

```bash
python3 -m venv .venv
./.venv/bin/python3 -m pip install -r requirements.txt
```

В выводе должна появиться строка `Successfully installed chromadb-1.5.9`. Колесо весит около
22 МБ: с версии 1.0 ядро Chroma собрано на Rust и приезжает бинарником.

Проверка:

```bash
./.venv/bin/python3 -c "import chromadb; print(chromadb.__version__)"
```

Ожидаемый вывод: `1.5.9`.

## Шаг 2. Поднять Ollama и скачать модель эмбеддингов

```bash
ollama serve &
ollama pull nomic-embed-text
curl -s http://localhost:11434/api/tags | head -c 200
```

Признак успеха: `curl` возвращает JSON со списком моделей, и `nomic-embed-text` в нём есть.
Если сервер не отвечает, дальше идти бессмысленно: без него Chroma не получит векторы.

## Шаг 3. Создать коллекцию и вставить документы

```bash
./.venv/bin/python3 basic_collection.py
```

Ожидаемый вывод:

```
документов в коллекции: 12
вставка 12 документов: 0.30 с
на документ: 0.03 с

запрос выполнен за 51.4 мс
  0.2119  [ai]  Эмбеддинг это плотный числовой вектор, который кодирует смысл текста.
  ...
размерность вектора: 768
```

Цифры на вашей машине будут другими, важна структура вывода: количество документов совпало,
поиск вернул три результата с расстояниями по возрастанию, размерность вектора равна 768.

Рядом со скриптом появится папка `chroma_data`. Внутри неё SQLite-файл с документами и
метаданными плюс файлы индекса. Это и есть вся база: ни сервера, ни отдельного демона.

## Шаг 4. Проверить фильтры

```bash
./.venv/bin/python3 filters_and_search.py
```

Скрипт открывает ту же папку заново, поэтому первая строка вывода должна показать
`коллекция открыта заново, документов: 12`. Если там ноль, значит шаг 3 не отработал или
скрипты запускались из разных каталогов.

Дальше идут пять блоков: векторный поиск с предфильтром по метаданным, составной фильтр с
`$and`, `$gte` и `$in`, поиск подстроки `$contains`, регулярное выражение `$regex` и
комбинация смыслового запроса с фильтром по тексту.

## Если не так

**`InvalidArgumentError: Validation error: name`.** Имя коллекции должно быть длиной от 3 до
512 символов из набора `[a-zA-Z0-9._-]`, начинаться и заканчиваться буквой или цифрой.
Короткие технические имена вроде `t` или `db` не пройдут.

**Вставка идёт минутами.** Первый запрос к Ollama после старта загружает модель в память, и
он всегда самый медленный. Замеряйте со второго прогона, а не с первого.

**`Connection refused` на порт 11434.** Ollama после перезагрузки системы сама не стартует,
её нужно поднимать командой `ollama serve`.

**Расстояния выглядят странно большими.** По умолчанию Chroma считает квадрат евклидова
расстояния (`l2`). В демо коллекция создаётся с `{"hnsw": {"space": "cosine"}}`, и метрика
задаётся только в момент создания: у существующей коллекции её уже не поменять, придётся
пересоздавать.

**Повторный запуск даёт другие цифры вставки.** `basic_collection.py` намеренно удаляет папку
`chroma_data` в начале, чтобы замер шёл по пустой коллекции. Если вам нужно сохранить данные
между запусками, закомментируйте блок с `shutil.rmtree`.
